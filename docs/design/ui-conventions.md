# MidiAppBox 対話規約(UI conventions)

- 確定: Phase 18a(2026-09-20、承認済み)。記録は `docs/results/phase18a.md`
- 対象: **MidiAppBox 上で動く全アプリ**。アプリ固有の画面設計は各アプリの仕様書
  (`docs/apps/<app>/`)に置き、本書は「どのアプリでも同じにする操作の語彙」だけを決める
- 実装: ジェスチャ判定と画面スタックは **`wasm-apps/appui`**(no_std crate)。
  ホストは生のイベントだけを渡す(ホストごとの解釈差を作らない。`docs/architecture.md` §11-11)

## 1. 思想

- **専用ボタンを極力設けない。** 画面は情報のために使い、操作は
  タップ・長押し・スワイプ・ハードウェアキーに寄せる。
- **階層はスタック。** 深く入ると情報が詳しくなり、ハードウェアキーで戻る。
- **状態表示がそのまま操作面になる**(BPM の表示をタップするとテンポの画面に入る、など)。

## 2. 入力の語彙

| 入力 | 意味 | 備考 |
|---|---|---|
| タップ | その階層の**主アクション**(一覧の行 = 進む、要素の選択) | |
| 長押し(600ms) | その要素の**強いアクション**。無い画面では主アクションと同じ | 成立したら**点滅**、**指を離したときに実行** |
| **長押し + ドラッグ**(速さ = シャトル) | 値の**連続変更**。**変位が「速さ」**になり、指を止めていても変わり続ける。中央に戻すと止まる | Phase 18b。成立(点滅)してから 12px を超えて動かすと入る。**広い範囲の値**向き(sequencer の BPM 40〜240 は 12px で 1bpm/秒、40px で 4、80px で 12) |
| **長押し + ドラッグ**(位置) | 値を**変位に比例して段階的に**変える。指を止めれば値も止まる | Phase 18d。**狭い範囲の値**向き(sequencer の拍子は 16px で 1 段。**左右 = 分子、上下 = 分母**)。同じジェスチャで「速さ」と「位置」を使い分けるので、**どちらかはアプリが要素ごとに決める** |
| 縦スワイプ | リストのスクロール(指に追従、慣性なし) | 長押しを経ていないドラッグはこちら |
| **横スワイプ** | **ページ送り**(Phase 21a)。**`Gesture::allow_hswipe` を立てている画面だけ**で、押下 1 回につき 1 度だけ向きが返る。指追従の連続スクロールにはしない | **立てていない画面では従来どおり**タップ・長押しを取り消すだけで何も起きない。**縦が優先**(大きいほうの軸で決める既存規則は不変) |
| **パンくずのタップ** | **1 階層戻る**(ヘッダ左)。最上位では**何もしない**(アプリを終了させるのは HW キーだけ) | Phase 18b |
| **`-` の長押し / `+` のタップ** | 要素の**削除 / 追加**。行の頭に `-` が縦に並び、最後の要素の次の行に `+` を置く | Phase 18c |
| **HW キー短押し** | **1 階層戻る。最上位ならアプリ終了** | 実機 = 電源キー、Linux ホスト = Backspace |
| HW キー 1〜2 秒 | **強制ホーム**(アプリに聞かずホストが停止) | 脱出路。Linux ホストは ESC |
| HW キー 2 秒以上 | 電源断(実機・電池運転のみ) | 既存。変更しない |

### 壊す操作は長押し(Phase 18c で一般化)

- **消す・戻せない操作は長押しで確定する**(成立したら点滅 → 指を離して実行)。
  **足す・戻せる操作は 1 タップ**でよい。確認ダイアログは作らない(画面と操作面を使うため)。
- **できない操作は記号ごと出さない**(暗くするのではなく空白にする)。
  行の文字色は 1 行 1 色なので、`-` だけ色を変えられないという実装上の制約にも合う。
  例: 再生中の Session、上限に達した追加、最後の 1 つの削除。
- **`[Phase 20 で追記]` 「消す」だけでなく「置き換える」も長押し**である。
  ファイルの**上書き保存**と**読み込み**(今の編集内容を捨てる)は長押しで確定し、
  **空きスロットへの保存だけが 1 タップ**(足す操作なので)。
  **操作の手引きと結果はステータス行とヘッダ右を差し替えて出す**(専用の表示領域を作らない。
  描画スロットは座標キーで解放されないため。Phase 19b の名称変更と同じ手)。

### 専用ボタンを置いてよい条件

1. **演奏中に 1 タップで届く必要がある主操作**(Play / Stop、演奏に関わるトグル)。
2. **状態を常に見せる必要があり、その表示自体が操作面になるもの**(トグルの ON/OFF)。

遷移のためだけのボタン(`BACK` / `OPEN`)、スクロールのためだけのボタン(`^` `v`)は**置かない**。

## 3. しきい値(論理座標 320×240。1px ≒ 0.22mm)

| 名前 | 値 | 意味 |
|---|---|---|
| `TAP_MAX_MOVE` | 12px | これを超えて動いたらタップ・長押しにしない |
| `LONG_PRESS_MS` | 600ms | 長押しの成立時間 |
| `SWIPE_MIN_MOVE` | 24px | これを超えたらスワイプ(縦横は大きいほうの軸で決める) |

- **デッドゾーン(12〜24px)で押下を終わらせない。** MOVE は刻んで届くので、
  ここで打ち切るとスワイプ閾値に達する前にジェスチャが死ぬ(Phase 18a で踏んだ)。
  「タップ・長押しは無効。ただしスワイプにはなりうる」状態として続ける。
- **長押しが成立した後のドラッグはシャトル**(値の連続変更)であって、スクロールではない。
  成立した時点でジェスチャはその要素のものになる(Phase 18b で改めた。18a は取り消してスクロールにしていた)。

## 3.5 タイル(Phase 19a)

一覧が「行」なのに対し、**演奏中に見て触る画面は「タイル」**にする(遠目に見分けられ、指の的が大きい)。

| 要素 | 決め |
|---|---|
| 並べ方 | 横 4 × 縦 2 の 8 枚。**9 枚目以降は縦スワイプ**(1 段 = タイルの行 = 4 枚、指追従) |
| **タップ** | その要素の**主アクション**。sequencer では**ジャンプ**(再生中は次の小節境界、停止中は開始位置の選択) |
| **左上の `✕` の帯(26×26)の長押し** | **削除**。行の `-` に相当する(壊す操作は長押し。§2) |
| **それ以外の帯の長押し** | **掘り下げ**(一覧の「進む」に相当) |
| **再生中の要素** | **背景を拍に同期して点滅**(行では `>` 1 文字でやっていることを、タイルでは背景でやる) |
| 選択カーソル | 背景色(点滅しない)。既存と同じ |
| **画面外に出た再生中の要素** | **追う**。ただし**手動スクロールの後は、次にその要素が変わるまで追わない**(演奏中に的が入れ替わらないように) |

**実装上の注意**: 描画スロットは座標キーで解放されないので、**行とタイルは同じ領域を取り合う**。
使っていない側は **`fill_rect` を `w = h = 0` で描いて消す**(スロットは `(x, y)` で引かれるので増えない)。

### タイルを「格子」として使う(Phase 21a)

タイルは**要素の一覧**だけでなく、**格子(グリッド)**にも使える。sequencer のドラムパターンは
**4 列 × 2 行**を「**横 = 16 分のステップ、縦 = サウンド**」として使っている。

| 要素 | 決め |
|---|---|
| **1 画面の意味** | **1 拍**(16 分 × 4)。**全体のどこを見ているかはステータス行に出す**(`B1.3` = 1 小節目の 3 拍目) |
| **横スワイプ** | **ページ送り**(1 回 = 1 拍)。§2 の解禁はこの用途のため |
| **縦スワイプ** | **サウンドの組のページ送り**(一覧のスクロールではない) |
| **タップ** | **そのサウンドを鳴らす(試聴)。状態は変えない** |
| **上の帯(26px)の長押し** | **セルの ON / OFF**(Song タイルの `✕` の帯と同じ「帯 = 状態を変える」) |
| **本体の長押し + 上下ドラッグ** | **値**(ベロシティ)。**「位置」で決める**。**ドラッグせずに離したら ON / OFF** |

- **帯 = 状態、本体 = 値**という切り分けは、Song タイルの「`✕` = 削除 / 名前 = 名称変更 / 本体 = 中身」と同じ発想である。
- **「長押しで入って、離すまでに動かしたかどうかで意味が決まる」**形は、
  **押した時点でデータを書き換えない**こと(書き換えるとトグルと打ち消し合う。Phase 21a で踏んだ)。

## 3.6 編集モード(Phase 19b)

**要素を長押しすると、その要素が「編集モード」に入る**(指を離しても点滅が続く)。
それまでの長押し(§2「成立したら点滅、指を離したときに実行」)と違い、**長押しは実行ではなく
モードの切り替え**になる。**壊す操作を長押しで確定する**という §2 の原則は、
**「編集モードに入っていること自体が確認になる」**という形に置き換わる。

| 編集モード中の操作 | 意味 |
|---|---|
| **左上の `✕` をタップ** | **削除**(通常時は `✕` を出さない) |
| **名前をタップ** | **名称変更**(プリセットの一覧 + ダッシュ) |
| **ドラッグ** | **並べ替え**(落とし先を選択色で見せ、離して確定) |
| それ以外をタップ | その要素の中身へ入る |
| **空白 / 他の要素 / HW キー / パンくず** | **モードを抜ける**(他の要素の長押しは対象が移る) |

- **通常時の見た目を汚さない**: 削除の `✕` のような「編集のための記号」は、
  編集モードのときだけ出す(演奏中に見る画面は情報だけにする)。
- **再生中は編集モードに入れない**(構造を変えると先読みと食い違うため)。
  長押しは「中へ入る」の従来動作に戻る。
- **ドラッグは `Gesture::allow_drag` を立てている間だけ**有効(`wasm-apps/appui`)。
  立てない画面では従来どおり縦スワイプ = スクロール、横は取り消し。
- **名前は自由入力を作らず、プリセット + ダッシュ**(`A` / `A'` / `A''`)で組み立てる。
  **同じ名前は同じオブジェクト**として束ねる(名前を既存のものに変えると、その定義への参照になる)。

## 4. 点滅の使い分け(意味が衝突しないこと)

| 何 | 表現 | 周期 |
|---|---|---|
| 再生中マーカー | 行頭の `>` 1 文字の表示 / 非表示 | **拍に同期**(拍頭から半拍) |
| 長押しフィードバック | 行(セル)の**背景色**をハイライト色と交互 | **200ms 固定** |
| **値の変更中**(シャトル) | **文字色**を編集色(黄)と通常色で交互 | **200ms 固定**(背景を持たない要素はこちら。Phase 18b) |
| 選択カーソル | 行の背景色(点滅しない) | — |
| **編集モードの対象**(Phase 19b) | 要素の**背景色**をハイライト色と交互 | **200ms 固定**(長押しの点滅と同じ。**離しても続く**のが違い) |
| **ドラッグの落とし先**(Phase 19b) | 落とし先の**背景色**(点滅しない) | — |

### 状態の色(Phase 18b)

`hostapi_draw_text_rgb` が使えるので、**トグルの ON/OFF は文字色**で示す
(背景色は選択カーソルに残す。両方を背景でやると衝突する)。

| 状態 | 色 |
|---|---|
| ON / 実行できる | 緑 |
| OFF | 灰 |
| その画面では意味が無い | 暗い灰(操作も受け付けない) |
| 停止(押すと止まる) | 赤 |
| 値の変更中 | 黄(点滅) |

**記号**: 再生 / 停止は **U+F04B(▶)/ U+F04D(■)**(実機の LVGL フォントにある FontAwesome)。
Linux ホストはこの 2 つを図形として描くので、**アプリは同じバイト列を書けばよい**。

- **点滅している = 離せば何か起きる。** 長押しに固有の意味が無い要素では点滅させない
  (例: 停止中の小節。長押しはタップと同じ「選択」になる)。
- `app_tick` は 100ms 周期なので、点滅はこの粒度で描かれる。

## 5. 画面スタックとアプリ終了

- アプリは `appui::ScreenStack` を持つ。最上位(レベル 0)がアプリのトップ画面。
- ハードウェアキーはホストが**任意 export `app_key(key_id, action) -> i32`** で渡す
  (`shared/hostapi_defs.h`)。アプリは `ScreenStack::pop()` の結果で返す:
  - `Pop::Popped(_)` → **0 以外**を返す(アプリが処理した = 実行を続ける)
  - `Pop::Exit` → **0** を返す(ホストの既定動作 = アプリ停止)
- **`app_key` を export しないアプリは、キー短押しで即終了する**(Phase 18a 以前と同じ)。
  既存アプリを作り替える必要はない。
- **画面を降りても再生は止まらない。** Transport は装置に 1 つで、画面はそれを覗く窓
  (`docs/apps/sequencer/spec.md` §4)。アプリを抜けたらホストが停止する。
- 再生中は、どの画面からでも止められる手段を残す(sequencer はステータス行右の ■)。
- **戻るはハードウェアキーとパンくずの 2 通り**。アプリを終了させるのは HW キーだけにする。

## 6. ホスト側の約束(実装者向け)

- 押下中の移動は `HOSTAPI_EV_TOUCH_MOVE` で届く。**8px 未満は間引かれ、キュー末尾の MOVE は
  上書きされる**(畳み込み)。アプリは「MOVE は間引かれる。最新座標だけ使う」前提で書く。
- キーはイベントキューではなく `app_tick` の切れ目で `app_key` に渡る(時刻は付かない)。
  時刻が要る入力が出てきたら、そのときイベント側に KEY を足す。
- 実機の強制ホームは電源キー 1〜2 秒。**`app_tick` が返らないアプリは止められない**
  (WAMR の実行中断は使っていない)。
