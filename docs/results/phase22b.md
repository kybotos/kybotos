## ステップ 3: 操作(BPM のシャトルと拍子のドラッグ)

- **仮のボタン(BPM- / BPM+ / BEAT)と長押しの連打を外し、appui の `Gesture` に置き換えた**(D9。`Cargo.toml` に `appui = { path = "../appui" }`)。
  押した位置で的を決める: 本体の左(x < 215、y 50〜178)とヘッダ右(x ≥ 200)= BPM、本体の右 = 拍子、ステータス行の右 = ▶ / ■。
  - **BPM = 長押し + 左右ドラッグ(シャトル)**。段階表は Sequencer と同じ(12px で 1bpm/秒、40px で 4、80px で 12)。速さを時間で積分し、端数は mbpm で持ち越す。
  - **拍子 = 長押し + ドラッグ(位置)**。左右 = 分子 1〜16、上へ = 細かい音価(2 → 4 → 8 → 16)、16px で 1 段。**ドラッグ中は確定前の値を出し、離したときに確定**(D11)。
  - **長押しが成立したら、変える値(数字。BPM はヘッダ右も)を黄とクリームで 200ms ごとに点滅**(ui-conventions §4)。
  - ▶ / ■ はタップ(離したとき)。長押しのまま離しても同じ(長押しに意味が無い要素。ui-conventions §2)。
  - 停止中だけステータス行の左に `hold + drag`(くすんだ緑。D8)。
- **拍 = 分母の音符**にした(`PPQN * 4 / den`)。`tempomap_set_meter(0, num, den)`。供給の先読みは 2 小節(最大 32 拍)。
- **演奏中の変更の反映(D11)**:
  - **BPM: 次の拍の頭の song tick にテンポを書く**(小節はやり直さない)。同じ拍の間の変更は同じ at_tick の上書きなので、
    **エントリは 1 拍に 1 件しか増えない**。満杯になればホストが通過済みの区間を畳む(`docs/hostapi.md` §4、Phase 17)。
    キューのイベントは playback tick で積んであるので、テンポが変わっても積み直さない。
  - **拍子: 小節をやり直す。やり直し方を「locate(0) して at_tick=0 を上書き」(Phase 13〜)から、
    stop → `tempomap_clear` → at_tick=0 の初期値 → start に変えた**。前者だと、シャトルで先の位置に書いたテンポのエントリが
    マップに残り、やり直した後にその位置で古いテンポが効いてしまうため(clear は STOPPED 中しか効かない)。
    **外の MIDI 機器には Stop / Start(0xFC / 0xFA)が出る**ようになる(前は locate だったのでクロックは途切れず、Stop / Start も出なかった)。
    小節の頭から始め直すことが外の機器にも伝わるので、こちらのほうが合っていると判断した。
  - 再生の開始も同じ手順(stop → clear → 初期値 → start)。前は clear していなかった。
- **Linux で確認**(`scripts/metronome-shots.sh`、画面は `captures/phase22b-step3/`):
  - `drag 270 110 48 0 800` → 4/4 → **7/4**、`drag 270 110 0 -16 800` → **7/8**、再生中に `drag 270 110 -32 16 800` → **5/4**。
  - 長押しの最中(`armed.png`)は BPM の数字とヘッダ右が黄。再生中は手引きが消える。
  - BPM のシャトル: `drag 100 110 100 0 800` で +1(コマンドの入口の `drag` は動かしてすぐ離すので、速さの段に居る時間が短い)。
    指を止めたまま変わり続けることは、**実機で手で確かめる**(ステップ 5)。
- **演奏中の BPM の変更を音で確認**(`METRONOME_WAV=... metronome-shots.sh`、解析は新しく足した **`scripts/metronome_clicks.py`**。
  ベル 150ms とクリック 60ms を音の長さで見分ける)。120bpm で鳴らし、3 秒後からシャトルで 124bpm へ:
  クリックの間隔は **500 → 495 → 489 → 483ms と拍ごとに縮み、ベルの並びは `Bccc Bccc ...` のまま途切れない**
  (小節をやり直していない)。間隔の ±6ms の揺れは Linux ホストがブロックの頭に丸めるためで、変える前の 120bpm でも出ている。
- 撮影スクリプトに **`async <手順>`**(長押しの最中を撮る)と **`METRONOME_WAV`**(WAV に録る)を足した。
  引数なしの `wait` がホストまで待って止まる不具合を直した(裏の手順だけを待つ)。
- **回帰のシナリオ**: BPM+ のタップを外し、**再生中の拍子のドラッグ(小節をやり直す経路)**を通すようにした:
  `expect 120bpm; expect hold + drag; expect ▶; tap 300 38; expect ■; wait 2; drag 270 110 16 0 800; expect ■; wait 1; tap 300 38; expect ▶`
  (▶ / ■ は conf では `\xef\x81\x8b` / `\xef\x81\x8d`)。
- **Linux の回帰 3 本 PASS**(`captures/phase22b-step3-regress`): metronome highmark **27,680**(appui を取り込んで `.wasm` が 4.0 → 5.8KB)、
  mp3player 19,112、hostapi_check 34,728(後の 2 本は不変)。

## ステップ 4: 拍の表示

- **下端(y 184〜230)に、分子の数だけ枠を 1 段で並べた**(全体の幅 304px で一定、1 枠は最大 72px、8 拍までは間隔 4px、9 拍以上は 2px)。
  今の拍の枠を点ける(1 拍目は橙、他は若葉)。
- **スロットの制約への対処(着手時に分かったこと)**: 枠の位置は拍子で変わるが、**スロットは座標で引かれて解放されない**
  (Linux の `native_hostapi_fill_rect` も実機の `hostapi.cpp` も、同じ座標が無ければ空きを新しく取り、消す手段は無い)。
  枠ごとに矩形を置くと、拍子 1〜16 の全部で **136 か所**になり、残りの 27 枚に入らない。そこで:
  - **左端をそろえた矩形の塗り重ね**にした。最後の枠から順に「その枠の右端までの色付きの層」と「その枠の左端までの黒の層」を重ねると、
    上の層が左側を塗り直すので、枠と隙間が残る。**層の起点は画面の左外(x = −1, −2, …)に 1px ずつずらす**(スロットの座標を分けるため。
    はみ出した部分はどちらのホストでも切られる)。**拍子によらず 32 枚(16 拍 × 2)**。重なり順は最初に描いた順なので、
    `app_init` で層 0(一番下)から順に作る。拍が進むときは、前の枠と今の枠の色付きの層の 2 枚だけ描き直す。
  - 足りない分は、**7 セグメントで出ない画を一度も描かない**ことで空けた(拍子の 10 の位は「1」だけなので b・c の 2 画、
    BPM の 100 の位は「1」「2」だけなので f を除く 6 画。計 11 枚減)。
- **拍の番号は 8 拍まで**(ステップ 0 の追記「入らないときは出さない」の具体化)。番号の文字も座標でスロットを取るので、
  全拍子の全位置に出すと 136 か所になる。1〜8 拍の位置(計 36 か所)だけにした。9 拍以上は枠が 32px 以下で、10 以上の 2 桁は入らない。
- **スロットの使用**: 矩形 = 背景 3 + BPM 20 + 拍子 19 + 拍の枠 32 = **74 / 80**、文字 = 4 + 拍の番号 最大 36 = **最大 40 / 80**。
