### 0-2. 決めること(推奨案)

| # | 項目 | 推奨 | 理由・代案 |
|---|---|---|---|
| **D1** | 画面の骨格 | **案 A**。上に**ヘッダ(26px、左 `Metronome`)+ ステータス行(24px、右端 ▶ / ■)**、残りが本体 | ヘッダとステータス行で Sequencer と同じ「どこに何があるか」になる(統一感)。代わりに縦 50px を数字に回せないが、案 A でも BPM は 104px あり十分に大きい |
| **D2** | 大きな数字の描き方 | **案 A = アプリが `fill_rect` の 7 セグメントで描く**(Host API 不変) | rect 69 / 80 で収まる。字形はモックアップのとおり。Host API に大きな文字を足す案 B は、今回の 1 アプリのためには重い(実機のフォントの flash、API の追加)。他のアプリでも要るようになったら改めて検討する |
| **D3** | BPM の変え方 | **BPM の数字の上(本体の左 x 0〜214、y 50〜176)で長押し + 左右ドラッグ = シャトル**。段階表は Sequencer と同じ(12px で 1bpm/秒、40px で 4、80px で 12)。**ヘッダ右の `120bpm` の長押しも同じ**(Sequencer の操作の場所でも効くように) | BPM- / BPM+ / -1 / +1 のボタンは無くす。縦方向は使わない(拍子の上下と取り違えないように) |
| **D4** | 拍子の変え方と範囲 | **拍子の分数の上(x 215〜320、y 50〜176)で長押し + ドラッグ(位置)**。左右 = 分子 1〜16、上へ = 細かい音価(分母 2 / 4 / 8 / 16)、16px で 1 段。既定 4/4。**拍は分母の音符**(6/8 は 8 分で 6 回) | Sequencer と同じ範囲・同じ向き。範囲を絞る理由は拍の表示だけだったが、2 段の枠で 16 まで収まった |
| **D5** | 拍の進み具合の表示 | **分子の数だけ枠を下端(y 184〜230)に並べ、全体の幅は一定。8 拍までは 1 段(1 枠は最大 72px)、9 拍以上は 2 段**(上段 = 前半)。今の拍の枠を点け、**枠の中に拍の番号**(Sequencer の小節インジケータと同じ考え方) | 1 段のままだと 16 拍で 1 枠 15px になり番号が入らない(`A4b`)。2 段なら 16 拍でも 1 枠 34×21px |
| **D6** | 配色 | **本体は黒、ヘッダはメニューの濃緑 `0x183c29` に文字はクリーム `0xf3f1e4`、ステータス行は黒に近い緑 `0x0b140f`、大きな数字はクリーム、拍の点灯は若葉 `0x8fd18b`、消灯の枠 `0x1c2620`**。**1 拍目のアクセントは橙 `0xf0a040`**(`A2`)か**クリーム**(`A7`。ロゴの色だけで済む)のどちらか。▶ 緑 / ■ 赤 / 変更中の黄は規約の色 | アクセントはユーザーに選んでもらう。**配色の値の置き場所**は、今は metronome の中の定数にし、mp3player を作り直すときに `appui` へ `theme` として移す(使う側が 2 つになってから共有する) |
| **D7** | BPM の文字をヘッダ右にも出すか | **出す**(`120bpm`。変更中は黄) | 本体の数字と重複するが、Sequencer と同じ場所に同じ表示がある(統一感)、**回帰で BPM が読める唯一の手がかり**(数字は矩形なので読めない)、D3 で操作の場所にもなる |
| **D8** | 手引き | **停止中だけ、ステータス行の左に `hold + drag` を暗い色で**出す。再生中は消す | ジェスチャは見えないので、単機能アプリでは最初の 1 回の手がかりが要る。再生中は情報を減らす |
| **D9** | appui を使うか | **使う**(`Gesture` だけ。画面は 1 枚なので `ScreenStack` は使わない) | 長押し・シャトルの判定を自前で持たない。SDK のサンプルにもなる |
| **D10** | 回帰のシナリオ | `expect 120bpm; expect \xef\x81\x8b; tap 300 38; expect \xef\x81\x8d; wait 2; tap 300 38; expect \xef\x81\x8b` の形(▶ → ■ → ▶ と、ヘッダ右の BPM を見る)。拍子を見るかは D12 | BPM のシャトルは値が揺れるのでシナリオでは使わない |
| **D11** | 演奏中に BPM・拍子を変えたときの音 | **拍子: 離したときに 1 回だけ反映**(今と同じ「その場で小節をやり直す」)。**BPM: シャトル中は 1 拍ごとに反映**し、**小節をやり直さない**(次の拍の頭からテンポが変わる) | BPM を今の方式(変わるたびに locate)で反映するとクリックが詰まる(F7)。1 拍ごとの反映は、テンポマップを「次の拍の位置に 1 エントリ」で上書きする形にする(エントリを増やさない書き方をステップ 3 で確かめる)。代案: BPM も離したときに 1 回だけ反映(簡単だが、ドラッグ中に耳でテンポを探れない) |
| **D12** | 拍子を回帰で読むか | **読まない**(拍子は本体の矩形でしか出ないので、ドラッグは Linux / 実機のスクリーンショットで見る) | 読むなら、ヘッダ右を `120bpm 4/4` にして `drag 270 110 16 0 800; expect 5/4` を足す手がある(Sequencer は再生中にヘッダ右に拍子を出している)。統一感の点ではこちらも筋が通るが、本体の表示と重複が増える |
| **D13** | 再生 / 停止の当たり判定 | **ステータス行の右 x 240〜320(y 26〜50)** | ▶ は 12px の記号なので、演奏中に 1 タップで届くよう広げる(ui-conventions §2「専用ボタンを置いてよい条件」1) |

### 0-4. ユーザーの決定(2026-10-03)

- **D1: 案 A**(BPM を左に巨大、拍子を右に分数、下端に拍の枠、ヘッダ右に `120bpm`)。
- **D6: 1 拍目のアクセントは橙 `0xf0a040`**。
- **D11: 再生中の BPM のシャトルは 1 拍ごとに反映**(小節はやり直さない)。拍子は離したときに 1 回反映。
- **D12: 拍子は回帰で読まない**(ヘッダ右は `120bpm` だけ)。
- その他(D2〜D5、D7〜D10、D13)は 0-2 の推奨案のまま。
- **D5 の変更(ユーザー判断): 拍の枠は 9 拍以上でも 1 段**(最大 16。`A4b-play16.png` で問題ないと判断)。
  16 拍で 1 枠 約 15〜17px になり **2 桁の拍の番号が枠に入らない**(`A4b` で `11` がはみ出している)ので、
  **9 拍以上は枠の間隔を 4 → 2px に詰め、それでも番号が枠の幅に入らないときは番号を出さない**(拍は点いている枠の位置で分かる)。
  入るかどうかは実機の Montserrat 14 の字幅で決まるので、ステップ 4 で実機とスクリーンショットで確かめる。

## ステップ 1: 画面の骨格と配色

- **ヘッダ(26px、濃緑 `0x183c29`)+ ステータス行(24px、`0x0b140f`)+ 黒の本体**にし、タイトルを `Metronome`(クリーム)に、
  **START / STOP のボタンをステータス行右の ▶ / ■ に**置き換えた(当たり判定は x 240〜320。D13)。ヘッダ右に `120bpm`(D7)。
- 拍のランプの色をステップ 0 の配色に(消灯 `0x1c2620`、点灯 若葉、1 拍目 橙)。BPM- / BPM+ / -1 / +1 / BEAT のボタンは
  **ステップ 3 で外すまで仮に残した**(緑系に塗り替えただけ。`beats/bar: 4` の行も同じ)。
- 文字はすべて `hostapi_draw_text_rgb` にした(色付きの文字のため。`hostapi_draw_text` は使わなくなった)。
- 撮影用に **`scripts/metronome-shots.sh`** を足した(ホストを FIFO つきで起動し、引数の手順どおりに操作・撮影・`texts`。§3.6 の手順をまとめたもの)。
  画面は `captures/phase22b-step1/stop.png` / `play.png`。
- **回帰のシナリオ**(`scripts/device-regress.conf` の `SCENARIO[metronome]`)を新しい画面に合わせた:

  ▶ / ■ は `texts` の `\xNN` の表記のまま `expect` で一致した(F3)。BPM+ のタップはステップ 3 で外すときに直す。
