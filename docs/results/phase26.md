### 0-b. I2C(I2C_NUM_1、IO15 / 16)

起動時のタッチのドライバのスキャンと `p26scan` の両方で、**0x36・0x38・0x48 が応答し、0x52 は応答しない**(rev-a は RTC 未実装のとおり)。

| デバイス | 読んだレジスタ | 値 | 判定 |
|---|---|---|---|
| MAX17048(0x36) | VERSION(0x08) | `0x0012` | ✅ 0x001x(データシートの値) |
| ADS1115(0x48) | CONFIG(0x01) | `0x8583` | ✅ 電源投入時の既定値 |

残量計の値(VCELL 78.125µV/LSB、SOC 1/256 %、CRATE 0.208 %/h 符号つき):

| 状態 | VCELL | SOC | CRATE |
|---|---|---|---|
| USB のみ、**電池なし**、IO2 未操作 | 4.115 V | 99.1 % | −10.6 %/h |
| USB + 電池、IO2 = HIGH の直後 | 3.884 V | 62.8 % | −3.7 %/h |
| 同上、約 70 秒後 | 4.009 V | 63.4 % | **+10.4 %/h** |

- **電池が無くても残量計は応答し、もっともらしい値を返す**(VBAT に充電回路の出力が Q1 の内部のダイオードを通って出ているため。P3 の「USB のみで VBAT 4.31 V」)。
  26a で残量計を使うとき、**値だけで電池の有無は判定できない**(Phase 25 の ADC と同じ結論)。
- CRATE は更新が遅い(HIGH にした直後はまだ負で、約 1 分後に正)。

### 0-c. MIDI(J6、I/O 基板の MIDI の回路)

最初は I/O 基板の MIDI の IN / OUT を配線していなかったので後回しにし、配線が済んでから(同じ日)Phase 24c と同じ手順で確かめた
(`KYBOTOS_DEV_APPS=1`、`midi_loopback`、UM-ONE は PC から `hw:1,0,0`。ログは `captures/phase26/midi.log`)。ファームの MIDI の設定は Phase 24c のまま
(`MIDI OUT ready (GPIO17, 31250bps, TXD inverted)` / `MIDI IN ready (GPIO18, RX not inverted)`)。

**MIDI IN**(PC の `amidi -S` で送り、`midi_loopback` の画面をシリアルの `texts` で読んだ)

| 送ったもの | 画面(受信バイト数 / 直近の 16 進) | 判定 |
|---|---|---|
| (何も送らない) | `FE` のみ(12 バイト) | ✅ UM-ONE の Active Sensing |
| `90 3C 64 80 3C 00 B0 07 7F` | `FE FE FE 90 3C 64 80 3C` / `00 B0 07 7F FE FE FE FE` | ✅ 順序どおり、欠けなし |
| ランニングステータス 13 バイト | `40 7F 43 7F 47 7F 40 00` / `43 00 47 00 FE FE FE FE` | ✅ |
| SysEx `F0 7D` + 299 バイト + `F7`(302 バイト) | 受信数 58 → 371、末尾 `… 28 29 2A F7` | △ 末尾まで届くが、**`MIDI RX: ring buffer full, dropped oldest record` が 5 件** |

- SysEx の警告: 302 バイトは受信のリング(256 件)より大きく、アプリは 100ms ごとに最大 64 バイトしか読まないので、読み出しのタイミングによってはあふれる。
  Phase 24c(同じファームの設定、同じ送り方)では出なかった。**配線ではなく受信側のバッファとアプリの読み方の性質**と見て、ここでは追わない
  (長い SysEx を受けるアプリの需要が出たら、リングの大きさかアプリの読み方を見直す)。UART のエラー(framing / FIFO overflow)は 0 件。

**MIDI OUT**(PC の `amidi -d -a -c` で受け、`midi_loopback` の START / STOP をシリアルの `tap` で押した)

| 区間 | PC で受けたもの | 判定 |
|---|---|---|
| 何もしない 4 秒 | 0 バイト | ✅ |
| START → 約 3 秒 → STOP | `FA` 1、`F8` 151、`FC` 1 | ✅ 120bpm で毎秒 48 個の見込みどおり |

### 0-d. IO2(HOLD)による電池の経路(USB + 電池、ユーザーがテスターで測定)

TP1 = VBAT(電池側)、TP2 = VBAT_SW(J10 へ行く側)。

| IO2 | TP1(VBAT) | TP2(VBAT_SW) | 残量計 | CHG の LED |
|---|---|---|---|---|
| HIGH(`p26latch 1`) | 4.01 V | 4.04 V | CRATE +10.4 %/h(充電) | 赤(充電中) |
| LOW(`p26latch 0`) | 3.908 V | 4.28 V | — | 緑(電池が見えない) |

- **HIGH で Q1 が ON になり、電池が充電される**(VBAT_SW が VBAT より少し高く、残量計の VCELL もテスターの VBAT と一致)。
- **LOW では電池が切り離され**、VBAT は開放電圧へ下がり、VBAT_SW は充電回路の無負荷の出力(4.28 V)になる。
  → P2 のとおり、**USB で起動したときも HOLD を HIGH にしないと充電されない**。

### 気づいたこと

- **電池を J1 につないだ瞬間に、USB 給電中の CrowPanel が 1 回再起動した**(ログで起動のやり直し。リセットの理由の行はモニタに出ていない)。
  電池をつないだときに VBAT_SW(充電回路の出力 4.3〜4.7 V)へ電池が Q1 の内部のダイオードの向きで引き込まれ、電源が一瞬下がったと推測する。
  普段の使い方(電池をつないだまま)では起きない操作なので、記録だけにする。
- IO1(ホームキー)は今までどおり。電池の経路をキーで ON にするのは D1 経由で、ファームの動きには関係しない。

### 0-e. `docs/boards.md` の更新案

ステップ 3 で反映する(ステップ 1・2 の結果も入れるため)。

- **§3-3 の端子**: J8 / J9 に I/O 基板が載る、J6 は I/O 基板の MIDI へ線、J10 は I/O 基板の VBAT_SW から線(電池は I/O 基板の J1)。
- **§4**: CrowPanel の電源キー / 自己保持の動き(ステップ 1 で決まったもの)、電池の経路は HOLD が HIGH のときだけ ON(USB でも上げないと充電されない)、
  リセット中は HOLD が LOW になるので電池のみでは電源が切れる。
- **新しい節「CrowPanel の I/O 基板(rev-a)」**: 機能・ピン・アドレスの表(指示書の P1)、rev-a で未実装のもの(RTC)、ステップ 0 の実測。

## ステップ 1: 実装(2026-11-07)

承認された動き(指示書の追記 2 つ)で実装した(`9709114`)。

- ボードの記述: `crowpanel_adv28.h` に `KB_HAS_POWER_LATCH 1`、`PIN_PWR_LATCH GPIO_NUM_2`、`KB_PWR_HOLD_ALWAYS 1`。`board_pins.hpp` に既定値 `KB_PWR_HOLD_ALWAYS 0`(Waveshare の今の動き)。
- `power_key`: `PowerKeyConfig::hold_always`。init の最初で HOLD を HIGH(ログ `PWR: hold ON at boot (key pressed: battery start | no key: external power start)`)。
  2 秒に達したら(押したまま)`on_power_off`(アプリの強制停止を最大 3 秒待つ → バックライトを消す)→ HOLD を LOW。
  離してから 1 秒後も動いていれば HOLD を HIGH に戻し、`on_power_restore`(バックライトを点ける)。ディープスリープには入らない。
  `hold_always` が偽なら今までの経路(Waveshare は変わらない)。
- **電源キーのタスクのスタック**: 最初の版(離してから止める)で、離したときに `pwr_key_loop` がスタックをあふれさせて再起動した(2048B)。
  `KB_PWR_HOLD_ALWAYS` のボードだけ 3072B にした(Waveshare は 2048B のまま)。

### 充電が止まる(DONE のまま)問題

CHG の LED は TP4059 の CHRG / DONE の表示(赤 = 充電中、緑 = DONE)。**HOLD が HIGH なのに TP4059 が DONE のままで充電しない**ことがあった。

| 場面 | LED | 電池 |
|---|---|---|
| 回帰と焼き込みのあと(リセットが何度も入った) | 緑 | TP1 3.96 V / TP2 3.959 V(Q1 は ON、充電電流なし) |
| 電源が切れた状態で USB を挿す → USB の給電で起動、約 1 秒後に HOLD を上げる | 緑のまま | — |
| その状態で HOLD を 3 秒 LOW → HIGH(`p26latch`) | 緑のまま | VCELL 3.977 V で一定 |
| **電池で動作中(HOLD = HIGH)に USB を挿す** | **赤**(ずっと) | 充電 |
| 充電中に ESP32 をリセット(モニタの起動し直し。HOLD が約 1 秒 LOW) | **緑**になった | VCELL 4.018 → 4.000 V と下がる |
| 充電中に長押し(USB 給電中。HOLD が離してから 1 秒 LOW) | 緑 → 赤 | 充電(ステップ 2 の上の表) |
| ステップ 0: USB のみで起動 → 電池を J1 につなぐ → 数分後に HOLD を上げる | 赤 | 充電 |

- **TP4059 は、電池が一度見えなくなると(充電回路の出力が無負荷になると)DONE に入り、その後に電池がつながっても再開しないことがある。** 再開するときとしないときの条件は分かっていない
  (1 秒の LOW で戻ったこともある。電池の電圧は 3.98 V で再充電のしきい値より下のはずなのに再開しない)。
- 確実に充電されるのは、**TP4059 の電源(USB)が立ち上がるときに電池が見えている**場合(電池で動作中に USB を挿す)。
- ファームが HOLD を上げられるのは起動から約 1 秒後で、リセット中は R3 で LOW になる。**USB を挿したときとリセットのたびに電池が切り離される**のは回路の性質で、ファームでは避けられない。

- ユーザーの判断(2026-11-07): **制約として記録して進める**(指示書の追記)。当面の使い方は「**充電するときは、電池で起動してから USB を挿す**」。
  回路側の対策(USB があるときはファームに関係なく Q1 を ON にする、など)と、TP4059 が再開する条件の切り分けは roadmap の U-38。

### 満充電

上の使い方(電池で動作中に USB を挿す → LED が赤)で充電し、LED が緑になったときの電池側の電圧(TP1)を測る。

| 項目 | 値 |
|---|---|
| 満充電(LED 緑)の TP1 | **先送り**(2026-11-07) → 同じ日に測定: **4.15 V** ✅(4.2 V 以下) |
| 同じときの TP2(VBAT_SW) | 4.15 V |

- 締めの日に充電を始めたが LED が緑になる前にユーザーが外出することになり、安全のため充電を止めた。**測定は先送りにして Phase 26 を閉じる**(ユーザー判断。roadmap の U-40)。
  途中の値は 3.96 V 前後(ステップ 2)で、4.2 V に近い範囲はまだ測っていない。
- **追記(2026-11-07)**: 止めたあと同じ日に充電を再開して終わった(LED 緑、USB は挿したまま)。ユーザーのテスターで **TP1 4.15 V / TP2 4.15 V**。満充電で 4.2 V を超えないことを確かめたので U-40 をクローズした。

## まとめ

- I/O 基板(rev-a)は、I2C(0x36 / 0x38 / 0x48、0x52 なし)、MIDI の IN / OUT、IO2 による電池の経路の切り替えがどれも設計どおりに動く。`docs/boards.md` に反映した(§1、§3-1、§3-3、§3-4、§4、§5)。
- 電源の自己保持を実装した: 起動するたびに HOLD を上げる、2 秒の長押しで(押したまま)画面を消して HOLD を下げ、離したときに電源が切れる、USB 給電中なら戻す。Waveshare は変わらない。
- **制約: TP4059 は、電池が一度見えなくなると DONE に入って充電を再開しないことがある**。rev-a では「電池で起動してから USB を挿す」と確実に充電される。対策は U-38。
- 後の段(roadmap): 26a 残量計(MAX17048)、26b ペダル(ADS1115)、26c 外付けの DAC。
