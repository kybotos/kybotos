### 0-a. WAMR プールの PSRAM 化

**方式**: `runtime_init()` で `heap_caps_malloc(kPoolBytes, MALLOC_CAP_SPIRAM)` して
`init_args.mem_alloc_option.pool.heap_buf` に渡す。静的 BSS の `s_wamr_heap` は削除する。
19b の `.wasm` バッファと同じ手(`docs/results/phase19b.md`)。

- **アラインメント**: WAMR の pool allocator は先頭を自前で整列するが、念のため
  **`heap_caps_aligned_alloc(16, …)`** を使う。確保は**起動時 1 回だけ**で、解放しない。
- **失敗したときの扱い**: **ログを出して `runtime_init()` を false で返す**(internal への
  フォールバックは作らない)。`CONFIG_SPIRAM` は Phase 15 以降 常に有効で、
  **失敗は構成ミスなので隠さない**方がよい。呼び出し側は既に失敗を扱える。
- **大きさ**: **今回は 112KB のまま動かさない。** 変える変数を 1 つに絞って
  「PSRAM へ移したこと」の影響だけを測るため。**増やすのは 21a の仕事**
  (そのときは `.wasm` +1 B ≒ プール +2.42 B の実測から逆算する)。
- **Linux ホスト(`main.c` の 192KB)は静的のままにする。** x86_64 に PSRAM の概念は無く、
  ここを触っても得るものが無い。**理由を results に残す**という指示書の要求はこの段落で満たす。

**PSRAM 上でインタプリタを回す影響(本項の唯一の懸念)**

プールには **モジュールのロード結果**だけでなく **`create_exec_env` の WASM スタック 8KB** が載る。
19b で PSRAM に移したのは `.wasm` バイトコード(**読み出しが主**)だったのに対し、
**スタックは呼び出しのたびに読み書きする**ので、性質が違う。データキャッシュには乗るが、
**悪化しうる**という前提で測る。

実測項目(ステップ 1 で必ず記録する):

| 指標 | 比較対象 | 出所 |
|---|---|---|
| `app_tick` の avg / max | 19b の **avg 1,207µs** | 既設の jitter 統計(`wasm_runtime.cpp`) |
| 起床間隔の p50 / p95 / p99 / max | 既定原則の **ジッタ上限 5.1ms** | 同上 |
| プール消費(highmark)と残り | 20 の **101,384 / 114,496** | 既設のプール残量ログ(19a で追加) |
| 停止時の 4 値 | F14 | `device-regress.sh` |

**internal で取り戻せる量**: 静的 **−112KB**。ただし **§9 の表の「internal 固定」の行は
1 つも動かさない**(L0 キュー 4KB・テンポマップ・タスクスタック・DMA バッファ)。
取り戻した internal は **21a の `.wasm` 増加には使わない**(それはプール = PSRAM 側で賄う)。
**当面は余裕として持つ**のが本フェーズの立場である。

**回帰しきい値(`scripts/device-regress.conf`)**: 今回は**値が上がる**方向なので、
**新しい基準値から 8KB ほど下**という従来の置き方に従って**引き上げる**
(下げっぱなしにしない)。**`MIN_FREE_PSRAM` は逆に下げる**必要がある
(現在 8,000,000 に対して実測 8,316,904 = 余裕 316,904 B。112KB を PSRAM から取ると
**約 8,202,000 まで下がり余裕は 202KB**。21a でプールを増やすとさらに減るので、
**ここで 7,900,000 程度へ下げておく**)。**実測してから値を確定し、承認を得る**(ゲート 6)。

**`architecture.md` §9 の書き換え**: 表の「WAMR プール(65,536 B)| **internal 固定**」の行を
**PSRAM** に改め、「WAMR プールの大きさ」節に Phase 21 の段落を足す。
**internal 固定にしていた理由(7B-fix: 最大連続ブロックを linear memory に残す)は
Phase 15 の PSRAM 化で既に失効している**ことは §9 に明記済みなので、その続きとして書く。

### 0-b. ミキサの設計(実機。本フェーズの本体)

**方針: `click_task` を「1 音を書き切るタスク」から「常時ブロックを書くミキサタスク」に作り替える。**

| 項目 | 決め | 理由 |
|---|---|---|
| ブロック長 | **240 フレーム**(5.44ms @44.1kHz) | `dma_frame_num` と一致させ、書き込みがディスクリプタ境界に揃う |
| ボイス数 | **8**(静的配列) | ドラム 4 + クリック + 余裕。`Voice` は約 40 B なので 320 B |
| 書き込み | **常時**(鳴っていなければ無音ブロックを書く) | **アンダーフローを起こさない = F3 の二重クリックが構造的に消える**(F4) |
| ゼロ埋め | **やめる** | 上と同じ理由。**ただし「1 拍ごとのクリックを数分回して再発しない」ことを実測で確かめる**(ゲート) |
| タスク | 既存の `click` タスクを流用(**優先度 18 / 静的スタック 4096**) | 恒久物は静的確保(6B / 7B-fix の教訓)。ヒープから取らない |
| ブロックバッファ | `int16_t[240 * 2]` = 960 B。**タスクスタック上**(現行と同じ) | 小さいので静的にする必要が無い |
| 合成 | int32 で加算 → **±32767 にクランプ** | 4 音同時でサチュレートさせない(0-f) |
| MP3 との共存 | **排他。MP3 が PLAYING の間はミキサは書かない**(発音要求は捨てる) | F7。`write_fn` と `i2s_channel_write` を取り合わせない。**mp3player は元から音源を使わない**ので実害が無い |
| レート | ミキサは **44.1kHz / 16bit / stereo 固定**。MP3 が止まったら `ensure_i2s(44100,16,true)` で戻す | 現行 `tone_write_now` と同じ規律 |

**MP3 との排他の具体**: ミキサタスクのループは
「MP3 が PLAYING なら 10ms 待って continue / そうでなければ 1 ブロック合成して `i2s_write`」。
`i2s_channel_write` は DMA に空きが出るまでブロックするので、**このループ自体がペースを作る**
(タイマは要らない)。MP3 の開始・終了で `ensure_i2s` が走るのは従来どおり。

**CLICK ポートの扱い**: **残したままミキサのボイス 1 本に載せ替える。**
`hostapi_tone_define` / `tone_play` / `OP_TONE` の語彙・意味は**一切変えない**ので、
**`metronome` / `sequencer` / `seq_smoke` の `.wasm` は再ビルドしない**。
内部的には `Play_Tone(freq, dur, level)` が「SINE ボイスを 1 本確保する」に変わるだけ。
**これで「クリックとドラムが重なっても両方鳴る」**という副次的な改善も入る
(現在はクリックがドラムを待たせる)。

### 0-c. 発音タイミングの精度(いちばん悩ましい点。承認を仰ぎたい箇所)

**現状の数字**(F11 / F12): **Linux は 0〜23ms 遅れ、実機は 0〜5.4ms 遅れ**。
どちらも「次に書く/次に再生されるブロックの先頭」に丸められている。

ブロックミキサにすると、この丸めは**ブロック長のジッタ + 書き込み先行ぶんの固定遅延**になる。
**問題は、L0 が 20µs 前にしか発火しない(F9)こと**である。
ミキサが今から書くブロックは**すでに DMA に積まれたぶんだけ未来に鳴る**ので、
**「イベントが来た時点で、その時刻を含むブロックはもう書き終わっている」**。
つまり**先行時間が無いとサンプル精度には置けない**。

| 案 | 内容 | ジッタ | 遅延 | risk |
|---|---|---|---|---|
| **A** | ディスパッチャは触らない。ミキサは**次に書くブロックの先頭**に置く | **1 ブロック = 5.44ms** | **書き込み先行ぶん(ディスクリプタ 1〜2 本 = 5〜11ms)の固定遅延** | 低 |
| **B** | フックに**目標時刻(host_us)**を渡し、**SYNTH / CLICK だけ先行して取り出す**(ポート別の fire advance)。ミキサは Clock Authority の (frames, host_us) からブロック先頭の時刻を求め、**ブロック内のサンプルオフセット**に置く | **0(サンプル精度)** | **0(MIDI OUT と揃う)** | 中(**ディスパッチャに手が入る = V4 のリスク**) |

**推奨: A で実装し、実測してから B の要否を決める(同一フェーズ内)。**

理由:

- **A でも今より悪くならない。** 実機は 5.44ms のまま、**Linux は 23ms → 5.44ms で改善**する。
- 本当に効くのは**固定遅延のほう**(MIDI OUT で外部音源を鳴らしながら内蔵ドラムを鳴らすと、
  内蔵だけが一定量遅れる)。**これは「ずれの量」を測ってから判断すべきで、
  測る前にディスパッチャへ手を入れるのは順序が逆**である。
- **B に移る費用は小さい。** フックに `at_host_us` を最初から渡しておけば
  (A ではミキサが使わないだけ)、B への移行は**ポート別 advance の定数 1 つ**で済む。
  **したがってフックのシグネチャは最初から B の形にする。**

**遅延の測り方(ステップ 4)**: 同じ tick に **内蔵 SYNTH の音**と **MIDI OUT の Note On** を置き、
**外部音源の音と内蔵の音を 1 本のマイクで同時に録る**。波形上の 2 つのオンセットの差が
そのまま「内蔵の遅れ − 外部音源の遅れ」である。**10ms を超えたら B に進む**を判定線にしたい
(打楽器のフラム知覚が 10〜20ms あたりで始まるため)。**この判定線の承認を求める。**

**Linux 側**: `want.samples = 1024`(23.2ms)は**ブロックミキサと相性が悪い**ので、
**256(5.8ms)へ下げて実機のブロック長に近づける**。SDL のコールバックは 1 回で
1024 フレーム来ても、**内部を 240 フレームずつに切って処理する**形にすれば
両ホストで同じコードになる。**どちらにするかもステップ 0 の決定事項として承認を仰ぐ**
(推奨: **want.samples を 256 にし、コールバック内で 1 ブロックずつ回す**)。

**`app_tick`(100ms)とは無関係**であることの確認: 発音要求は L0 のタイマ(実機は
`ESP_TIMER_TASK`、Linux は `hook_arm`)から来るので、**アプリの tick ジッタには依存しない**。
これは現行のクリックと同じ構造で、変わらない。

### 0-d. 音色(合成)とサンプルへの差し替え境界

**4 音**(GM ドラムの番号に合わせる。0-e):

| 音 | note | 作り方 |
|---|---|---|
| Kick | 36 | **ピッチ掃引する減衰サイン**(約 110Hz → 45Hz、掃引 40ms、全長 180ms)+ 短いクリック成分 |
| Snare | 38 | **ノイズ + 190Hz の減衰サイン**を混ぜる(全長 140ms) |
| Closed Hi-Hat | 42 | **ノイズをハイパス**(1 次の差分で代用)、全長 45ms |
| Crash | 49 | **ノイズをハイパス**、**全長 800ms の緩い減衰** |

- **ノイズは xorshift32 の整数乱数**。**サンプルごとに `libm` を呼ばない**という既存の規律
  (再帰振動子の理由と同じ)を守る。
- サインは既存の**再帰振動子(回転行列)**をそのまま使う。ピッチ掃引は
  **ブロック単位で係数を差し替える**(サンプルごとに `cosf` を呼ばない)。
- エンベロープは既存と同じ**指数減衰**(乗算 1 回)。
- **`HOSTAPI_WAVE_*` に `NOISE` を足すか**: **足さない。** `tone_define` は
  クリック用の語彙のままにして、**ドラムの音色は note 番号で選ぶ**(0-e)。
  語彙を増やさないことが層の切り方の検証である(`hostapi.md` §0)。

**サンプルへの差し替え境界**: ボイスを

```c
typedef struct { uint8_t kind; uint8_t note; int32_t remaining; /* … 音色ごとの状態 … */ } Voice;
static void voice_start(Voice* v, uint8_t note, uint8_t velocity);
static void voice_render(Voice* v, int32_t* acc, int n);   /* ← ここだけ差し替わる */
```

の形にし、**`voice_render` の中身を PCM の読み出しに替えるだけでサンプル再生になる**ようにする。
**サンプルの読み込み・PSRAM への配置は本フェーズでは作らない**が、置き場の当たりは
**PSRAM に `heap_caps_malloc`、読み込みは `hostapi_fs_read`(Phase 20 で入れたもの)の再利用**。

### 0-e. Host API の語彙(承認の本体)

**提案: Host API の関数を 1 つも増やさない。**

アプリは既存の `hostapi_seq_write` に **`port = HOSTAPI_PORT_SYNTH`(= 2、既に enum にある)**の
イベントを積むだけにする。

```
{ tick: T, port: HOSTAPI_PORT_SYNTH, status: 0x99, data1: note, data2: velocity }
```

`shared/hostapi_defs.h` に書く契約:

| 項目 | 決め | 理由 |
|---|---|---|
| 見るイベント | **Note On(`0x9n`)で `velocity > 0` のものだけ** | 打楽器はワンショット |
| **Note Off / velocity 0 の Note On** | **無視する** | **21a のイベント数が半分になる**(4 声部 16 分で 128 → 64/小節。キュー深さ 256 に対して余裕が倍) |
| チャンネル(`0x9n` の `n`) | **無視する**。`0x90`〜`0x9F` のどれでもよい | **ポートが既に宛先を決めている**ので、チャンネルは二重の宛先指定になる |
| note 番号 | **GM ドラム準拠。v1 は 36 / 38 / 42 / 49 の 4 つ** | 外部音源へ同じ `data1` をそのまま出せる(21a 以降で MIDI と内蔵を選べる) |
| **未知の note** | **何もしない**(ログも出さない) | L0 のディスパッチャから呼ばれるのでログは禁止 |
| velocity | 1..127 を**ゲインに線形写像**。マスター音量と乗算 | `tone_define` の `level` と同じ規律 |
| 同時発音数 | **8** | 0-b |
| 溢れたとき | **同じ note の最も古いボイスを奪う。無ければ全体で最も古いものを奪う** | ハイハットの連打で自分を切る動きが自然 |
| `transport_stop` / アプリ破棄 | **鳴っているボイスを消す** | `seqcore_reset` と同じタイミング |
| 即時発音の口(`tone_play` 相当) | **作らない** | 予約は `seq_write` で足りる。UI のプレビューが要るなら 21a で判断する |

**`seqcore_hooks_t` への追加**(両ホスト同一):

```c
/* SYNTH ポートの発音。at_host_us はそのイベントが鳴るべき時刻(音楽時間軸)。
 * ロックの外から呼ばれる。ログ・確保・ブロッキングは禁止 */
void (*synth)(uint8_t note, uint8_t velocity, int64_t at_host_us);
```

**`at_host_us` は案 A では使わない**が、**B へ移るときにシグネチャを変えなくて済むように
最初から渡す**(0-c)。`port_dispatch()` の `default:` に `case HOSTAPI_PORT_SYNTH:` を足す。

**既存アプリへの影響はゼロ**: X-macro に追加が無く、既存の enum 値を使うだけなので、
**既存 5 本の `.wasm` は再ビルド不要**。`seqcore_hooks_t` は**ホスト内部の構造体**で
WASM の ABI ではない(両ホストのアダプタを同時に直せば済む)。

### 0-f. 音量

- **マスター音量(`hostapi_audio_set_volume`、既定 98)は従来どおり全部に掛かる**(P10)。
- **ボイスごとの基準レベル**は、**4 音同時 + クリックでも −3dBFS 程度に収まる**ように置く。
  現行のクリックは `amp = 12000 * level/100 * vol/100` なので、**ドラムは 8000 を基準**にして
  Kick だけ 10000(低域は体感が小さい)とする。**最終値は Linux の WAV でピークを見て決める。**
- 合成は **int32 で加算 → ±32767 にクランプ**。**クリップは起きない設計にするが、
  起きても歪むだけで落ちない**ようにする。

### 0-g. 検証の入口(4 音同時をどう確かめるか)

**推奨: 検証用アプリ `wasm-apps/synth_probe/` を 1 本足す**(指示書の選択肢 (i))。

- 理由: **`seq_smoke` は回帰 6 本の基準 `.wasm`** なので触りたくない。
  `metronome` の一時改造は**撤去の手間と事故**(18a / 19 の教訓)が付く。
  **7 本目を足しても消えるのは flash だけ**で、RAM もプールも食わない(P11)。
- 中身: タップ不要で `app_init` から走り、**(1) 4 音を同じ tick に置く → (2) 16 分の
  ハイハット連打 → (3) クリックとドラムを重ねる → (4) ボイスを溢れさせる**を
  一定のパターンで繰り返す。画面には打った音を数字で出すだけ(描画スロットは最小)。
- **回帰 6 本には入れない**(`device-regress.conf` の `APPS` は変えない)。
- **21a でドラム画面ができたら残すか消すかを再評価する**(results に申し送る)。

**機械判定の材料**: **Linux ホストの出力を WAV に落とす**。
`audio_callback` が書いたブロックを、**環境変数 `MIDIBOX_WAV_OUT` が設定されているときだけ**
ファイルへ追記する(既定 off なので既存の挙動は不変)。これで

- **4 音同時に 4 つの成分が乗っているか**(単音なら 1 つしか乗らない)
- **ピーク値**(0-f のクリップ判定)
- **オンセット間隔**(16 分のハイハットが等間隔か)

を**耳ではなく数値で**言える。**実機は耳 + カメラ録画**(`docs/workflow.md` §3.3)のまま。

### 0-i. 承認を仰ぎたい点(まとめ)

1. **WAMR プールを PSRAM へ移す**(`architecture.md` §9 の方針変更)。**大きさは 112KB のまま。**

3. **発音タイミングは案 A(ブロック先頭)で実装し、V6 の実測が 10ms を超えたら案 B

4. **Linux の `want.samples` を 1024 → 256 に下げる**(実機のブロック長に近づける)。

6. **検証用アプリ `synth_probe` を 1 本足す**(回帰 6 本には入れない)。
   **Linux に `MIDIBOX_WAV_OUT` の WAV 書き出しを足す**(既定 off)。
7. **回帰しきい値の更新**: `MIN_FREE_INT` / `MIN_LARGEST_INT` を**引き上げ**、

## Host API と seqcore_hooks_t の変更

**Host API の関数は 1 つも増やしていない**(0-e の推奨案どおり。X-macro は不変なので
**既存 5 本の `.wasm` は再ビルド不要**)。アプリは既存の `hostapi_seq_write` に積むだけ:

```
{ tick: T, port: HOSTAPI_PORT_SYNTH, status: 0x99, data1: note, data2: velocity }
```

| 変更 | 内容 |
|---|---|
| `shared/hostapi_defs.h` | SYNTH ポートの契約を追記。`HOSTAPI_SYNTH_VOICES`(8)と GM ドラムの note 定数 4 つ |
| `shared/seq_core.h` | `seqcore_hooks_t` に **`synth(note, velocity, at_host_us)`** を追加 |
| `shared/seq_core.c` | `port_dispatch()` に `case HOSTAPI_PORT_SYNTH`。**Note On で velocity > 0 のものだけ**を見る。`port_dispatch` に `at_host_us` を渡すため、**ロックの中で求めた `next_us` を引数で渡す**形にした(`host_us_of_locked` はロック下専用で、送出はロックの外のため) |
| 実機 | `seq::SetSynthHandler` → `hostapi.cpp` の `seq_synth_handler` → `audio::Play_Drum` |
| Linux | `hook_synth` → `host_synth_note` |

**`at_host_us` は案 A では使っていない**が、**案 B へ移るときにシグネチャを変えなくて済むよう
最初から渡している**(0-c の決定どおり)。

**契約の要点**(`shared/hostapi_defs.h` に記載):

- **Note Off と velocity 0 の Note On は無視**(打楽器はワンショット)。**21a のイベント数が半分になる。**
- **チャンネルは無視**(ポートが既に宛先を決めているので二重指定になる)。
- **note は GM ドラム準拠**: 36 Kick / 38 Snare / 42 Closed HH / 49 Crash。**未知の番号は何もしない。**
- **ボイスは 8 本**。溢れたら**同じ note の最も古いもの → 全体で最も古いもの**を奪う。
- **MP3 再生中は鳴らない**(実機は同じ I2S を `esp_audio_player` が使うため排他)。

## ステップ 2: 内蔵音源ポート(Linux)

Linux は元から**コールバック(pull)型の単声ミキサ**だったので、素直に 8 ボイス化した。

- `Voice` を `s_voices[8]` に。種類は `VK_TONE`(CLICK / `tone_play` の減衰サイン)と
  `VK_KICK` / `VK_SNARE` / `VK_HAT` / `VK_CRASH`。
- **ノイズは xorshift32**、サインは既存の**再帰振動子**、Kick のピッチ掃引は
  **ブロック単位で係数を作り直す**(サンプルごとに `libm` を呼ばない、という既存の規律を守った)。
- **`voice_render()` の中身だけ差し替えればサンプル再生になる**形にした(0-d の差し替え境界)。
- 発音要求を**キュー(`Req`、32 件)**にした。**単一の `s_click_asap` では、1 コールバックの間に
  来た複数の発音を落としていた**(4 音同時が原理的に作れない)。
- **`want.samples` を 1024 → 256**(23.2ms → 5.8ms)。実機のブロック長 5.44ms に近づけた。
- **`MIDIBOX_WAV_OUT`** を設定したときだけ、ミキサ出力を WAV に落とす(**既定 off**)。

### 検証用アプリ `wasm-apps/synth_probe/`(回帰 6 本には入れない)

タップ不要で `app_init` から 120bpm / 4/4 を走らせ、4 小節を 1 周として繰り返す。

| 1 | 4 音を**同じ tick**に | 単声なら 1 つしか鳴らない |
| 2 | 16 分のハイハット 16 発 | 粒とボイスの奪い合い |
| 3 | クリック + ドラム | 従来はクリックがドラムを待たせた |

**さらに小節 8 で `test.mp3` を再生し、小節 12 で止める**(V7 を自動化するために後から追加。

## ステップ 3: 内蔵音源ポート(実機ミキサ)

**`click_task` を「1 音を書き切るタスク」から「常時 1 ブロック(240 フレーム)を書き続けるミキサ」に
作り替えた。** 音色の式は Linux と同一。

- **7B-fix のゼロ埋めをやめた。** 二重クリックの真因は**クリック終端の DMA アンダーフロー**で
  `auto_clear` とプリフェッチが競合することだった。**常時書いていればアンダーフロー自体が起きない**ので、
  対策の前提が消える(`docs/results/phase07.md` に「Linux は pull 型ミキサなので起きない」と当時から
  記録されていたことの裏返し)。
- **CLICK ポートはミキサのボイス 1 本に載せ替えた。** `tone_define` / `tone_play` / `OP_TONE` の
  語彙・意味は不変なので **`metronome` / `sequencer` / `seq_smoke` は再ビルドしていない**。
  副次的に「**クリックとドラムが重なっても両方鳴る**」ようになった。
- ミキサのバッファ(`s_acc` / `s_chunk`、各 960 B)とボイスは**静的**に置いた(6B / 7B-fix の教訓)。
- `i2s_channel_write` がループのペースを作るので、タイマは要らない。

### MP3 との共存で踏んだ不具合(ユーザー報告 → 修正)

**症状**: **mp3player を止めたあと、metronome も synth_probe も音が出ない**(再起動するまで)。
**ログには何も出ない。**

**原因は 2 つあり、どちらも「ミキサが常時書くようになって初めて届くようになった」経路だった。**

1. **`reconfig_rate()` がチャネルを無効のまま放置していた。**
   `i2s_channel_disable()` が失敗すると**その場で `return false`** していたので、
   **一度失敗するとチャネルが無効のまま固定**され、以後 `ensure_i2s` を呼ぶたびに
   同じ場所で失敗し続ける(**しかも無言**)。MP3 の開始・終了で `audio_player` が
   `clk_set_fn` → `reconfig_rate`(disable → 設定 → enable の 3 段)を呼ぶタイミングと、
   ミキサの `i2s_channel_write` が重なる窓が、**常時書き込みで初めて現実になった**。
2. **`audio_player_get_state()` は停止後に `PAUSE` のまま戻らない。**
   `Mp3Player::stop()` は `pause()` を経由するが、コンポーネント側で **IDLE への遷移は
   「`state == PLAYING` かつキューが空」のときだけ**(`audio_player.cpp` の外側ループは
   `PLAYING` 以外だと `portMAX_DELAY` で待つので、タイムアウト側の IDLE 遷移に到達しない)。
   `is_paused()` を見ていたミキサの抑止ガードは、**そこで永久に止まる**。

**対処(4 点)**:

- **I2S 専用ミューテックス**で「書き込み」と「再構成」を直列化した(静的確保)。
- **`reconfig_rate` を堅くした**: 既に無効なら `ESP_ERR_INVALID_STATE` を**失敗として扱わない**、
  途中で失敗しても**必ず `i2s_channel_enable` を試みる**、`enabled_` で有効・無効を記録する。
- **抑止ガードを自前の `mp3_active_`(atomic)に変えた**(`play_file` で立て、`stop` と
  自然終了のコールバックで倒す)。**コンポーネントの状態には依存しない。**
- **失敗を必ずログに出す**(`i2s_write` 失敗は間引いて WARN、再構成の失敗も WARN)。
  あわせて **`i2s_write` が失敗したら `enabled_ = false` にして次のループで作り直す**ようにしたので、
  **ミキサは自己修復する**。ミキサの抑止・再開も状態が変わったときだけ INFO で出す。

**確認**(`synth_probe` が自分で MP3 を再生・停止するので**物理操作なし**で再現できる):


(MP3 の前後で 8 秒周期の同じ構造が出ている)。**警告・エラー 0 件。**
