### 0-a. 音量を誰が持つか(契約変更の本体)

**決定: ホストが持ち、アプリをまたいで持続する。**

- **`hostapi_audio_reset()` から音量のリセットを外す**(F1)。
  アプリの起動 / 停止で**音量は変わらない**。
- **アプリが `hostapi_audio_set_volume` を呼んだら、そのままマスターを動かす**(案 i)。
  - **理由**: 語彙も挙動も増えない。**mp3player の V− / V+ はそのまま使え**、
    「アプリから触ったのに戻る」という現在の分かりにくさが消える。
  - 案 ii(アプリごとのゲイン × マスターの 2 段)は、**画面にマスターが無い状態で
    2 つの音量を持つと、どちらが効いているか分からなくなる**ので採らない。
    **音色ごとのバランス(所感 D-3)は別の軸**で、そちらは次フェーズ。
  - 案 iii(アプリからの変更を無視)は **mp3player の V− / V+ が死ぬ**ので採らない。
- **シグネチャは変えない。** 範囲 0..100、範囲外はクランプも従来どおり。

**`shared/hostapi_defs.h` の差分(案)**:

```
 *   hostapi_audio_set_volume(v)
-*     マスター音量 0..100(範囲外はクランプ)。MP3 とクリックの両方に適用
-*     (v2 で「MP3 の音量」から再定義)。曲をまたいで持続する。
-*     発音中のクリックには効かず、次の発音から有効。
+*     マスター音量 0..100(範囲外はクランプ)。MP3・クリック・内蔵音源のすべてに適用。
+*     **装置の設定であり、ホストが持つ(Phase 21b)。曲をまたいでも、
+*     アプリを切り替えても持続する**(アプリ起動時に既定値へは戻らない)。
+*     アプリからこれを呼ぶと**マスターそのものが動く**。
+*     発音中の音には効かず、次の発音から有効。
```

`docs/hostapi.md` §7 の audio の行にも同じ趣旨を書く。
**「アプリ起動時: … audio は STOPPED」という共通契約の行はそのまま**(再生状態の話なので)。

### 0-b. マスター設定の入口(承認の本体)

**ユーザー回答(2026-09-22)**: 「**マスター設定の移行方法は、アプリから独立している方が良さそう。
ただ HW のダブルクリックは分かりづらい。メニューの上の方(画面外)から下方向にスワイプした
場合に出す**とかはできますか」「**UI アクションによる移行方法も案に含めてください**」。

**できる。** F3 のとおり **`y == 0` は「画面の上端、またはそれより上」**を意味するので、
**「上端で押し始めて下へ動く」= 画面外から入ってきたスワイプ**として表せる。
iOS / Android / Windows と同じ作りである。

| 案 | 入口 | 判定 | 評価 |
|---|---|---|---|
| **E(推奨)** | **上端からの下方向スワイプ** | `push_event` で **DOWN の `y <= EDGE_PX`** を見つけたら**その DOWN をアプリへ配送せず保留**し、続く MOVE が**下へ `EDGE_PULL_PX` 以上**動いたら**マスター設定を開き、その押下は最後までアプリへ渡さない**。条件を満たさずに動いた / 離したら、**保留していた DOWN を先に配送してから**通常どおり流す | **アプリを 1 行も変えずに全アプリで効く。** 見つけやすい。**上端の数 px でしか始まらない**ので既存の操作と衝突しない |
| A | HW キーのダブルクリック | `power_key` で検出 | ABI もアプリも変えないが**分かりづらい**(ユーザー却下) |
| B | 右上にホストのアイコン | 領域を予約 | **sequencer の BPM と衝突**(F6)。画面を動かす必要がある |
| **D(併用)** | **ランチャーのメニューに行を置く** | 既存の一覧 | **見つけられる**。E が効かないホスト(下記 Web)の受け皿にもなる |

**推奨: E + D の併用。**

**しきい値の案**(実測して決める): `EDGE_PX = 3`、`EDGE_PULL_PX = 24`(`SWIPE_MIN_MOVE` と同じ)。

**保留の必要性**(ここが設計の肝): DOWN を先に配送してしまうと、**エッジスワイプだと分かった
時点でアプリの押下を取り消す手段が無い**(ABI に cancel イベントが無く、
「DOWN を配送していない MOVE / UP は捨てる」規則の裏返しで、**DOWN だけ配送された状態**が残る)。
**`appui::Gesture` は離されないまま 600ms で長押しを発火してしまう**ので、
**上端の DOWN は結論が出るまで保留する**のが正しい。**保留するのは `y <= 3` の押下だけ**なので、
**通常の操作は 1 つも遅れない。**

**ホストごとの差(Web 版の考慮。ユーザー指摘)**:

- **実機**: 上端からのスワイプはこの装置だけのものなので、そのまま使える。
- **Linux(SDL)**: ウィンドウ内の `y = 0` は押せるので同じ判定が使える。
- **ブラウザ(将来。roadmap U-10)**: **上端からのスワイプは OS / ブラウザが先に取る**
  (モバイルの通知シェードや pull-to-refresh、デスクトップではタブバー)。
  **Web 版では E が使えない可能性が高い。**
  → **だから D(メニューの行)を併用する**。
  **「入口はホストごとに違ってよい。設定そのものはホストが持つ」**という形にしておけば、
  Web 版は自分に合う入口(ボタンやキーボードショートカット)を選べる。
  **アプリ側は入口を一切知らない**ので、移植で壊れない。

**開いている間のふるまい**:

| 項目 | 決め |
|---|---|
| `app_tick` | **止めない。** 再生は続き、アプリの画面も更新され続ける(下に見える) |
| 音 | **止めない**(音量を変えながら聴けることが目的) |
| タッチ | **アプリへ配送しない**(`push_event` で捨てる)。設定は LVGL が直接受ける |
| HW キー | **短押しで設定を閉じる**(アプリには渡さない)。強制ホーム / 電源断は従来どおり |
| 閉じ方 | **設定の外側をタップ / HW キー短押し / 閉じるボタン** |
| 描画 | **`lv_layer_top()`** に置く(F4)。**アプリの描画スロットは 1 つも使わない** |

### 0-c. マスター設定の画面(ホストが描く)

#### 完全な画面遷移ではなく、**オーバーレイにできる**(ユーザーの質問への回答)

**できる。** この装置の LVGL は **9.5** で、**`lv_layer_top()`** がある
(`src/managed_components/lvgl__lvgl/src/display/lv_display.h`)。

- `lv_layer_top()` は**アクティブな画面より上に合成される層**で、
  **画面を切り替えずにその上へ重ねられる**。
- **アプリの画面(`s_screen`)はそのまま残り、下に見え続ける。**
  アプリは**自分が覆われたことを知らない**(描画も `app_tick` も止めない)。
- **メニュー画面でも同じ層が使える**ので、**アプリ実行中でもランチャーでも同じ実装**で出せる。
- `screensaver.cpp` が既に**全画面の不透明オーバーレイ + クリックを食う**形を実装済みで、
  **作り方の前例になる**(違いは「メニュー画面の子」ではなく「top 層」に置くこと)。

**ただし全画面を半透明で覆うのは避ける。** 半透明の合成は**毎フレーム全面の
ブレンドを要求する**ので、PSRAM の描画バッファ(Phase 15)では割に合わない。

**推奨する見た目**:

```
 ┌────────────────────────────────┐ ← 画面上端から降りてくる
 │  Settings                   ✕  │   **不透明の帯**(高さ 約110px)
 │                                │
 │  Volume   [ − ]  50  [ + ]     │   ← 1 項目 = ラベル + 操作 + 値
 │           ▓▓▓▓▓▓░░░░░░         │   ← バー
 ├────────────────────────────────┤
 │                                │
 │   (下はアプリの画面がそのまま)  │ ← **覆わない。** 触っても
 │                                │    アプリには届かない(0-b)
 └────────────────────────────────┘
```

- **帯は不透明**(ブレンド無し)。**下半分は覆わない**ので、
  **合成のコストは帯の面積だけ**で済む。
- **帯の外をタップすると閉じる**(iOS の引き下ろしと同じ感覚)。
  ただし**そのタップはアプリに渡さない**(閉じるためだけに使う)。
- 項目が増えたら**帯が縦に伸びる**(v2 で MIDI 設定が入る)。

#### 項目の作り

- **`screensaver.cpp` と同じく LVGL を直書き**する。`hostapi_draw_*` は**使わない**
  (あれはアプリのスロットで、ホストが使うと衝突する)。
- **v1 の項目は「音量」1 つ**。ただし**項目が増える形**にする
  (**ユーザーの想定: MIDI 設定**。Web から WASM を動かすときに要る)。
  → **1 項目 = ラベル + 操作 + 値**を 1 行に置き、**縦に積める**ようにする。

#### 音量の操作(ユーザー回答で確定)

**`[ − ]` / `[ + ]` は 1 刻み。長押しで変化量(連打間隔)が増える。バーも入れる。**

**既存の作り(metronome の BPM±、Phase 7D)をそのまま移す**:

| 保持時間 | 連打間隔 |
|---|---|
| 押下直後 | **1 ステップ**(即座に) |
| 500ms 後〜 | 400ms ごと |
| 1,500ms 後〜 | 200ms ごと |
| 3,000ms 後〜 | 100ms ごと |

- **1 刻み**なので、0〜100 を端まで送るのに最速でも約 10 秒。**実用上は十分**
  (既定値の周辺で微調整するのが主な用途)。
- **ホスト側は `appui` を使えない**(あれは wasm 用の crate)ので、
  **LVGL の `LV_EVENT_PRESSED` / `LV_EVENT_RELEASED` + `lv_timer`** で同じ形を作る。
- **バーは入れる**(`lv_bar`)。**実際に使って要否を判断する**(ユーザー指示)。
- **値は数値でも出す**(ユーザーが「いくつ」と決めて伝えられるように。0-f)。

## ステップ 1: 音量をホストの設定にする

- **`hostapi_audio_reset()` から音量のリセットを外した**(両ホスト)。アプリの起動 / 停止で
  音量は変わらなくなった。
- **既定値 98 → 50**(実機 `Mp3Player::kDefaultVolume` / Linux `DEFAULT_MASTER_VOL`。
  **両ホストで同じ値にする**とコメントで縛った)。
- **契約を書き換えた**(`shared/hostapi_defs.h` の audio、`docs/hostapi.md` §7)。
  シグネチャは不変、**アプリが呼ぶとマスターそのものが動く**(案 i)。

**実測(Linux の WAV。同じドラムパターンのピーク)**:

| 音量 | ピーク | |
|---|---|---|
| 98(Phase 21a) | 24,016 | 基準 |
| **50(新しい既定)** | **12,255** | 比 **0.510**(50/98 = 0.510 と一致) |
| **metronome で 88 にしてから sequencer** | **21,106** | 予想 21,565。**アプリをまたいで保たれた** |

### 見落とし(ユーザー判断で A を採用)

**既存アプリが音量の初期値を 98 と思い込んでいる**:
`metronome/src/lib.rs` と `mp3player/src/lib.rs` が `static mut VOLUME: i32 = 98;` を持つ。
ホストの既定が 50 になったので、**表示が実態とずれ、最初の `V−` は 50 → 88 に「上がる」**。

| 案 | 内容 | 判断 |
|---|---|---|
| **A(採用)** | **受け入れて記録する。** 一度 V± を押せばホストが追従する | **ユーザー承認(2026-09-22)** |
| B | 音量を読む Host API を足す | ゲート 3 に抵触 |
| C | 2 本を再ビルド | ゲート 4 に抵触 |

**A の根拠**: この 2 本は **D-18 / U-17「UI が古いので refine したい」の対象**で、
**マスター設定ができれば V± 自体が要らなくなる**。そこでまとめて直すのが筋。

## ステップ 2: マスター設定の画面と入口

### 共有ロジック(`shared/master_ui.c` / `.h`)

**ジェスチャ・開閉の状態・音量・連打加速・オーバーレイの座標と当たり判定**を
**両ホスト共通の C** に置いた(Phase 11 の「同じロジックを二重に書かない」に従う)。
**描画だけホストごと**(実機は LVGL、Linux は SDL)。

**上端スワイプの判定**:

- **`y <= MASTERUI_EDGE_PX`(3)で始まった押下だけを保留**する(アプリへ配送しない)。
  座標変換は画面外をクリップして 0 に張り付かせるので、**0 付近が「上端またはその上」**。
- **下へ `MASTERUI_PULL_PX`(24)動いたら開く**。この押下は最後までアプリへ渡さない。
- **上へ動いた / 明らかに横へ動いた(`|dx| > dy + 12`)ときだけ諦め**、
  **保留していた DOWN を先に流してから**通常どおり配送する。
- **保留するのは上端 3px の押下だけ**なので、通常の操作は 1 つも遅れない。

**なぜ保留するか**: DOWN を先に配送すると、エッジスワイプだと分かった時点で
**アプリの押下を取り消す手段が無い**(ABI に cancel イベントが無い)。
取り消せないと **`appui::Gesture` が離されないまま 600ms で長押しを発火**してしまう。

### 画面(オーバーレイ。完全な画面遷移ではない)

- **実機は `lv_layer_top()`**(LVGL 9.5)、**Linux は描画の最後に上から重ねる**。
- **帯は不透明**(高さ 110px)。**下半分は覆わない**ので、合成のコストは帯の面積だけ。
  **全画面の半透明は使わない**(毎フレームの全面ブレンドが高い)。
- **アプリの描画スロットを 1 つも使わない**(rect / text の数は不変)。
- **実機のオーバーレイのオブジェクトは CLICKABLE にしない。** 入力は下のアプリスクリーンの
  イベントコールバックで受け、**当たり判定は共有コードが持つ**(両ホストで同じ座標)。
- 項目は **ラベル + `−` + 値 + `+` + バー**の 1 行。**増えたら帯が縦に伸びる**形。

### 音量の操作

**1 刻み + 長押しで連打加速**(metronome の BPM± と同じ 500 / 1,500 / 3,000ms →
400 / 200 / 100ms)。**バーも出す**(要否は使ってから判断する。ユーザー指示)。
