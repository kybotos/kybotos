## ステップ 0: 確認と設計(2026-10-10)

### 0-a 実機で読む

一時のコード(`PHASE24A-TEMP`、`touch.cpp` の `KB_TOUCH_IC_NONE` の経路)で、0x38 のレジスタを読んだ。
I2C は port 1、100kHz、SDA=IO15 / SCL=IO16。INT(IO47)は内部プルアップの入力、RST(IO48)は出力。
ログは `captures/phase24a/probe.log`。読み終えた後、一時のコードは `git checkout` で外した(`git diff` 0 行)。

**ID などのレジスタ**

| 時点 | A3 チップ ID | A4 G_MODE | A6 ファームの版 | A8 ベンダー ID | 80 しきい値 | 88 報告の周期 | INT |
|---|---|---|---|---|---|---|---|
| 起動直後(リセットしない) | **0x64** | 0x01 | 0x03 | 0x88 | 0x16 | 0x0A | 1 |
| IO48 で 10ms リセット → 解除の 300ms 後 | 0x00 | 0x00 | 0x00 | 0x00 | 0x00 | 0x00 | 1 |

- **チップ ID 0x64 = FT6336U**(FT6x36 系の値)。Phase 24 の P1 の推定どおり。
- G_MODE=0x01 は「押している間 INT をパルスで出す」モード。
- **リセットの解除の直後から I2C は ACK を返す**(0ms)が、300ms 後でも ID のレジスタは 0x00 を返した。
  ただし、その後のタッチの読み出し(下)は正常。リセットの後しばらくは ID のレジスタが読めない(ファームの起動中に、レジスタの読み出しにだけ 0 を返す)と考えられる。
  データシートの Trsi(リセットから報告の開始まで 300ms 以上)は「報告」の話で、ID のレジスタが読めるまでの時間は書かれていない。

**押したときの読み出し**(`0x02`〜`0x06` を 20ms ごとに読み、変化したときだけ記録。ユーザーが左上 → 右上 → 左下 → 右下 → 中央の順に 1 秒ずつ押した)

| 押した場所 | 生の x | 生の y |
|---|---|---|
| 左上(題名のあたり) | 228 | 36 |
| 右上(`Settings` のあたり) | 217 | 285 |
| 左下 | 12 | 30 |
| 右下 | 6 | 284 |
| 中央 | 120 | 157 |

- **生の座標は縦置きの 240 × 320**(x は 0〜239、y は 0〜319)。
  **画面の横(左 → 右)= 生の y(増える)、画面の縦(上 → 下)= 239 − 生の x**。
  これは **Waveshare の CST328 で使っている変換(`TOUCH_ROT 1` = 90° 時計回り。`rx = ny`、`ry = (xmax − 1) − nx`)と同じ**。
  角の値が 0 / 239 / 319 に届いていないのは、押した位置が角から内側(題名や `Settings` の上)だったため。端まで届くかはステップ 2 で見る。
- 中央 (120, 157) → 画面の (157, 119)。論理座標 320 × 240 の中央 (160, 120) と合う。
- **イベント**(`0x03` の上位 2 bit): 押した瞬間 0、押している間 2、離したとき 1。離すと TD_STATUS(`0x02`)の点の数が 0 になる。
  座標のレジスタは離した後も最後の値が残る。
- **INT**: 押している間、約 100ms ごとに Low のパルス(G_MODE=1)。離すと止まる。
- ノイズの報告(押していないのに点の数が 1 になる)は、記録の間は無かった。

### 0-b 設計メモ(案。承認を求める)

**a. `touch.cpp` の分け方 — 同じファイルの中で、IC ごとの部分を `#if KB_TOUCH_IC == ...` で分ける**

- IC ごとに違うのは「初期化(アドレス、モードの切り替え)」と「生の座標と押しているかを読む(`read_raw_point`)」だけ。
  正規化・回転・LVGL の読み取り・注入・ログは共通に残す。
- `KB_TOUCH_IC_FT6336` を足し、FT6336 の部分を足す: 8 bit のレジスタの読み出し、初期化で `0xA3` を読んでチップ ID をログに出す
  (0x64 以外でも止めない)、`read_raw_point` は `0x02`〜`0x06` を 1 回で 5 バイト読み、点の数が 1 以上でイベントが「離した」でなければ押している。
- 別ファイル(`touch_cst328.cpp` / `touch_ft6336.cpp`)にしない理由: CST328 の部分は静的な変数と関数でできていて、切り出すと Waveshare の経路のコードが動く。
  IC は 2 つで、それぞれ数十行。3 つ目が来たら分ける。
- **Waveshare の経路が変わらないことの確かめ方**: 回帰 3 本と数値に加えて、**Waveshare のビルドの `touch.cpp.obj` の逆アセンブルを、変更の前後で比べる**
  (`objdump -d`。マクロの置き場所を変えるだけなら同じになるはず。違えば理由を書く)。

**b. リセットと INT — どちらも使わない**

- **リセットしない**(IO48 には触らない。Phase 24 と同じ)。リセットしなくても起動直後から読めた。リセットすると起動が 300ms 以上延び、
  その間は ID のレジスタも読めない。ESP32 のソフトリセットでタッチの IC がリセットされないことによる不具合が出たら、そのときに足す。
- **INT は使わずポーリング**(CST328 と同じ `TOUCH_FORCE_POLL 1`。LVGL の読み取りの周期ごとに 5 バイトを読む。100kHz で 1 回 0.6ms ほど)。
- I2C は CST328 と同じ 100kHz。

**c. 座標の変換 — ボードの記述の定数にする**

- `TOUCH_ROT`(今は `touch.cpp` の既定値 1)を、ボードの記述の **`KB_TOUCH_ROT`** に移す。両ボードとも 1。
- 生の範囲: CST328 は自分の分解能(240 × 320)を返すが、FT6336 は返さないので、**`KB_TOUCH_RAW_W` / `KB_TOUCH_RAW_H`(240 / 320)をボードの記述に持つ**
  (CST328 は読めた値を使い、読めなければこの値。今の Waveshare の挙動は変わらない)。
- 範囲の学習(`update_calibration`)の初期値: 今は CST328 用の固定値(x 1〜239、y 6〜298)。これを **ボードの記述の `KB_TOUCH_CAL_{X,Y}{MIN,MAX}`** に移す。
  CrowPanel は 0〜239 / 0〜319 で始め、ステップ 2 で端まで届くかを見て決める(範囲より外の値が来れば、今と同じく学習で広がる)。

**d. 2 点目** — 使わない(CST328 と同じく 1 点目だけ)。

**e. 確かめ方(ステップ 2)**

- **座標**: 一時に `DEBUG_TOUCH_CURSOR` を有効にしたファームで、画面のカーソルと座標のラベルを見ながら、四隅(角ぎりぎり)と中央を押す。
  ログの `BASIC: ... -> P(x,y)` を記録し、角で 0 / 319 / 239 付近まで届くこと、中央が (160, 120) 付近であることを確かめる。カメラでも撮る。
- **操作**: 指示書のステップ 2 の一連(メニュー → metronome → Settings → mp3player の一覧 → スクリーンセーバーの解除)をユーザーに頼み、
  ログ(`app: ...`、`texts`)とカメラで記録する。
- **注入との一致**: `Settings`(ヘッダ右)や metronome の ▶ を、指と `tap` で同じ座標として押し、同じ反応になること。
