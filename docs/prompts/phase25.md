## 目的

Waveshare ESP32-S3-Touch-LCD-2.8 の**電池電圧を読み、残量(%)にして、ホストの中で使える形にする**。
このフェーズは**検知まで**(表示は 25a、低電池の動きは 25b、アプリへ出す Host API は 25c)。
検知は**ボードの記述で有無を持たせ**、CrowPanel の I/O 基板に電池の検知が載ったときに同じコードを使えるようにする(Waveshare 専用にしない)。

## 前提(着手時に実機・資料で確かめ直す)

- **P1: 電池電圧の入口**: `docs/boards.md` §2-1 は GPIO8 を「wiki に記載なし。電池電圧の ADC の可能性があるが未確認」としている。
  ESP32-S3 では GPIO8 は ADC1 の CH7。**ステップ 0 で、回路図(Waveshare の公式資料。repo に無ければユーザーから受け取る)のネット名と、実測で確かめる。**
  分圧比も回路図から読み、実測で較正する。
- **P2: 電池**: J10(VBAT / GND)に **1 セルのリチウム電池**をつなぐ(手元は未接続。**ユーザーの作業**)。
  電池の種類・容量・保護回路の有無・満充電電圧は、ステップ 0 でユーザーに確認する。**極性と過放電に注意**(ユーザーが電池をつなぐ・外すとき、この指示書は手順を代行しない)。
- **P3: 電池モードの電源**: Waveshare は**電源キーを押して起動したときだけ**電池モード(自己保持 GPIO7 を HIGH)で、USB 給電で起動すると電池モードにならない
  (`power_key.cpp`。ログ `Battery mode: latch ON` / `External power: key control disabled`)。
  **電池だけで動かすと USB が無く、シリアルのコマンドとログが使えない** → ステップ 0 の電池だけの測定は、**画面の表示(一時のコード)かテスターの実測**で行う。
- **P4: 充電中の見え方**: USB 給電中に電池がつながっていると、充電の電圧が ADC に出て電池の電圧と区別がつかない可能性がある。
  充電 IC の状態(充電中・満充電)が ESP32 のピンに出ているかは、回路図で確かめる(出ていなければ「充電中」は電圧だけでは断定しない)。
- **P5: ADC**: ESP-IDF の oneshot ADC(`esp_adc/adc_oneshot.h`)+ キャリブレーション(`adc_cali`、eFuse があれば curve fitting)。
  減衰は 12dB 相当(分圧後は約 1.4V 以下の見込み)。ADC のノイズが大きいので複数回の平均(中央値など)を前提にする。

## ゲート

1. **Host API / ABI と `.wasm` は変えない。**(アプリへ出す 25c は別の承認のもとで、このフェーズには含まない)
2. **電池の種類・電圧 → 残量の変換のカーブ・「電池なし」の判定のしきい値は、実装の前にユーザーの承認を得る**(ステップ 0 の結果を添えて提案する)。
3. 一時的な計測コードは `PHASE25-TEMP` の目印を付け、済んだら撤去して `git diff` で残りが無いことを確かめる(workflow.md §3.2)。
4. **電池なし(USB のみ)でも、電池ありでも、既存の動作が変わらないこと**。ボードの記述で検知が無い(CrowPanel)の経路は**何も動かさない**(タスクも ADC も作らない)。
5. 回帰のしきい値(`scripts/device-regress.conf`)を変えたくなったら、変える前にユーザーの承認を得る(新しいタスクのぶん free_int が下がる見込み。基準値の更新として提案する)。
6. 公開の repo なので、非公開の repo の中身は書かない。

## スコープ

### 含む

- **ステップ 0: 確認(実機と資料。ユーザーの作業を含む)**
  - a. 回路図で、電池電圧のネット(GPIO8 か)、分圧の抵抗、充電 IC の状態の出力(ESP32 に出ているか)、電源キー / 自己保持との関係を読む。結果を `docs/boards.md` §2-1 の GPIO8 の行に反映する案を作る。
  - b. 一時のコード(`PHASE25-TEMP`)で GPIO8 の ADC1_CH7 を読む(生の値と mV、複数回の平均)。次の状態で、**テスターで測った J10 の電圧**と並べる:
    (1) USB のみ・電池なし、(2) USB + 電池(充電中の見え方)、(3) 電池のみ(電源キーで起動。USB が無いので値は画面に出す一時の表示で読む)、
    (4) 電池のみで MP3 / 内蔵音源を鳴らしているとき(**負荷で電圧がどれだけ下がるか**。25b の閾値の揺れの見積もりに使う)。
  - c. 分圧比と較正(ADC の値 → 電池の電圧)、電池なしの判定のしきい値、電圧 → 残量のカーブの案をまとめ、**ゲート 2 の承認を得る**。
- **ステップ 1: 実装**
  - ボードの記述に `KB_HAS_BATT_SENSE`(既定 0。`board_pins.hpp` に `#ifndef`)、`PIN_BAT_ADC`、分圧比(mV の換算に使う定数)を足す。Waveshare は 1、CrowPanel は 0。
  - 新しいコンポーネント(例 `src/components/battery/`)に、ADC の初期化・一定間隔(数秒おき)のサンプリング・平滑化・残量(%)への変換を置く。
    取り出す口は読み取り専用の関数(電圧 mV、残量 %、「電池あり / なし」、わかるなら充電中)。**スレッド安全**に、読む側が待たない形にする。
  - 起動時に 1 回、ログへ(`BATT: ...` に電圧と残量と、電池なしならそう)。`KB_HAS_BATT_SENSE` が 0 のボードでは何も初期化しない。
  - 電圧 → 残量の変換は、ボードや電池に依存する定数をボードの記述か 1 か所の表に置く(承認されたカーブ)。
- **ステップ 2: 確認用のシリアルコマンド `batt`**(`serial_cmd.cpp`。応答は `KBCMD: batt mv=... pct=... present=...`)。検知が無いボードでは `batt err not supported`。
  `docs/workflow.md` §3.4 のコマンドの表に 1 行足す。電池なし(USB のみ)と、(可能なら)USB + 電池で値を読み、ステップ 0 の実測と合うことを確かめる。
- **ステップ 3: 回帰と後片付け**
  - Waveshare を `KYBOTOS_DEV_APPS=1` で焼き、`device-regress.sh --board waveshare_lcd28` で**回帰 3 本 PASS**。新しいタスクのぶん free_int が下がるなら、新しい基準値を記録する(ゲート 5)。
  - **CrowPanel のビルドが通り、起動ログで電池のコードが動かないこと**(`BATT:` のログが無い、free_int が 24b の基準値 155,456 のまま)を確かめる。
  - 両ボードを普段使い(`KYBOTOS_DEV_APPS=0`)のファームに戻し、共用の SD の検査用アプリを消す。
  - 文書: `docs/results/phase25.md`、README のボードの表(要れば)、`docs/boards.md`(GPIO8 の行と §4 の電池の節)、roadmap(25 を done。25a の指示書へ引き継ぎ)、status、
    `docs/workflow.md`(`batt` コマンド、電池だけの測定の注意)/ `docs/lessons.md`(要れば)。

### 含まない

- ホストの画面への表示(25a)、低電池の警告と電源断(25b)、アプリへ出す Host API(25c)。
- 充電の制御、充電電流の測定、残量の学習(クーロンカウント)。
- バックライトの調光(U-34)、タッチの INT(U-33)。
- CrowPanel の I/O 基板の検討(Phase 26)。

## 完了条件

1. ステップ 0 の結果(回路図の読み、実測の表、分圧比、電池なしの判定、カーブの案)が `docs/results/phase25.md` にあり、ユーザーの承認を得ている。
2. Waveshare で電池電圧と残量が `batt` で読め、テスターの実測と合う(許容差は ステップ 0 で決める)。電池なしを判定できる。
3. Waveshare の回帰 3 本が PASS(基準値を更新したなら記録)。電池なし・ありで既存の動作が変わらない。Host API / ABI・`.wasm` は不変。
4. CrowPanel が電池のコードを動かさずにビルド・起動する(free_int が 24b の基準値のまま)。
5. 両ボードを普段使いのファームに戻し、SD の検査用アプリを消している。記録・roadmap・status・workflow を更新し、25a への引き継ぎ(取り出す関数の形、更新の間隔、判明した電圧の揺れ)を書いている。
