# Phase 22b: metronome を磨く(サンプルアプリとしての統一感と、単機能アプリとしての簡素さ)

- 契約日: 2026-10-03
- 参照: `docs/results/phase22a.md`(直前のフェーズ。メニューの配色 `shared/launcher_theme.h`)、
  `docs/design/ui-conventions.md`(対話規約: 長押し + ドラッグ、▶ / ■、状態の色、点滅)、
  `wasm-apps/metronome/src/lib.rs`(現状)、`wasm-apps/appui`(ジェスチャ判定)、
  `shared/hostapi_defs.h`(描画スロット、記号)、`scripts/device-regress.conf`(`SCENARIO[metronome]`)、
  `docs/roadmap.md` U-26(既存アプリの操作規約の統一)、`docs/workflow.md` §3.4 / §3.6 / §3.7
- 結果報告先: `docs/results/phase22b.md`

## 目的

metronome は Kybotos のサンプルアプリ(公開)で、実機で最初に触られるアプリの 1 つ。今の画面は Phase 7 の頃の作りのまま
(タイトル `metronome (wasm)`、BPM- / BPM+ / -1 / +1 / BEAT / START の 6 ボタン、拍子は 2 / 3 / 4 / 6 の巡回)で、
Phase 18 以降に決めた対話規約(`docs/design/ui-conventions.md`)とも、Sequencer アプリ(非公開の app-sequencer)の見た目とも揃っていない。

本フェーズで metronome を作り直す。方向は 2 つ:

1. **Kybotos のサンプルアプリとしての統一感**: タイトル・再生 / 停止・BPM の変え方・拍子の変え方を、
   Sequencer アプリ(= 対話規約の基準になっているアプリ)にできるだけ合わせる。
2. **単機能アプリとしての簡素さ**: 画面と操作を減らす。**大事なもの(BPM と拍子)は極端に大きく目立たせてよい**。

**この 2 つはぶつかる所がある**(下の「トレードオフ」)。ステップ 0 で案を並べ、ユーザーと決めてから実装する。

## 決定済みのスコープ(2026-10-03 のユーザー指示)

- **タイトルと再生 / 停止の UI は Sequencer にできるだけ合わせる。**
- **BPM の指定・拍子の指定も Sequencer に合わせる**(長押し + ドラッグ。拍子の範囲も Sequencer と同じにする方向)。
- ただし単機能アプリなので、**BPM と拍子の表示はできるだけ大きく(極端に目立って)よい**。
- **拍子の進み具合の表示は作り直す**(Sequencer に合わせると拍子のバリエーションが増え、今の 6 個のランプでは収まらない)。
- **配色はメニュー(Kybotos のロゴの色。`shared/launcher_theme.h`)に合わせるが、背景は基本黒**(焼き付きを避ける)。
- **タイトルの `(wasm)` は消す**(Phase 22a の「UI で WASM を意識させない」の続き)。
- 統一感と簡素さのトレードオフも含めて検討しながら進める(ステップ 0 で案を示し、決めてから実装)。

## 前提(着手時にソースで確認すること)

- **P1: 今の metronome**(`wasm-apps/metronome/src/lib.rs`、565 行、no_std、appui 不使用)。
  - 画面: タイトルバー(`0x903050`、40px)+ 背景 `0x101828`。`BPM: 120   beats/bar: 4` の 1 行、拍ランプ 6 個(44×36)、
    `-1` / `+1` の行、`BPM-` / `BPM+` / `BEAT` / `START` の行。
  - BPM 40〜240(±5 / ±1、長押しで連打加速)、拍子は **x/4 の 2 / 3 / 4 / 6 だけ**(`denom` は常に 4)。
  - 音は SYNTH の note 34(小節頭)/ 33(Phase 21c)。供給は `seq_write` で 2 小節先まで(Phase 13 の書き方)。
    **テンポ / 拍子の変更は「位置 0 へ locate して at_tick=0 を上書き」**(テンポマップのエントリを増やさない)。
  - `app_key` を export していない(HW キー短押し = 終了)。画面が 1 枚なので、これは規約(最上位ならアプリ終了)どおり。
- **P2: 文字は 1 サイズだけ。** 実機の LVGL は Montserrat 14(`CONFIG_LV_FONT_MONTSERRAT_14`)のみ、
  Linux は DejaVu を同じ大きさで描く。**Host API に文字の大きさを指定する手段は無い。**
  → 大きな数字は、(A) アプリが `fill_rect` で組む(7 セグメントなど)か、(B) Host API に大きい数字の描画を足すか、のどちらか。
- **P3: 描画スロット。** text 80 / rect 80(`shared/hostapi_defs.h` のコメントの「rect 48」は古い。roadmap の未割当課題)。
  スロットは `(x, y)` で引かれ、解放されない。**消すときは同じ `(x, y)` に `w = h = 0` で描く**(ui-conventions §3.5)。
  7 セグメントで BPM 3 桁 = 21 枚、拍子 `16/16` = 4 桁で 28 枚 + 斜線、拍の表示が最大 16 枚 + 枠で、**80 枚に近い**。
  Linux 側の上限も同じか確かめる。
- **P4: Sequencer の語彙(ui-conventions に書かれている範囲)。**
  - 画面上端に**ヘッダ**(左 = パンくず / 画面名、右 = BPM。停止中は `120bpm`)と**ステータス行**(右端に ▶ / ■)。
  - **BPM = ヘッダ右の長押し + 左右ドラッグ(シャトル = 変位が速さ)**。12px で 1bpm/秒、40px で 4、80px で 12。変更中は文字色が黄で点滅。
  - **拍子 = 長押し + ドラッグ(位置)**。**左右 = 分子(1〜16)、上下 = 分母(2 / 4 / 8 / 16)**、16px で 1 段。
  - **再生 / 停止 = U+F04B ▶(緑)/ U+F04D ■(赤)**。両ホストで描ける(Linux は図形)。
  - **拍 = 分母の音符**(Host API の transport の `beat` も、Sequencer の拍も `PPQN * 4 / den`)。
    6/8 なら 8 分音符ごとに 6 回鳴る。BPM は常に 4 分音符基準(`us_per_quarter`)。
- **P5: 回帰。** `SCENARIO[metronome]="expect START; tap 281 202; expect STOP; wait 2; tap 125 202; expect BPM: 125; tap 281 202; expect START"`
  (`scripts/device-regress.conf`。Linux も同じシナリオ)。**画面の文字だけを見る**ので、
  **`fill_rect` で描いた数字は回帰から読めない**。シナリオの語彙は `tap` / `hold X Y MS` / `drag X Y DX DY MS` / `expect` / `wait`。
  **`drag` は「MS だけ押してから 8 段 × 40ms で動かして離す」**ので、位置で決まる拍子は決定的に試せるが、
  速さで決まる BPM のシャトルは値が揺れる(期待値を決め打ちできない)。
- **P6: metronome の `.wasm` を作り直すので、Linux の highmark の基準(metronome 22,952)を取り直す**(Phase 21c と同じ扱い)。
  外のアプリ(app-sequencer)の回帰の conf は `device-regress.conf` を source するので、metronome のシナリオの変更はそちらにも乗る。
- **P7: appui** は app-sequencer がタグ(`appui-v0.1.0`)で依存している。**足すだけの変更なら壊さない**が、
  タグを切り直すかは別(外の追従は必要になったときに)。

## トレードオフ(ステップ 0 で決める論点)

| # | 論点 | 統一感に寄せると | 簡素さ・目立たせ方に寄せると |
|---|---|---|---|
| T1 | 画面の骨格 | ヘッダ + ステータス行(上の 50px)を Sequencer と同じに持つ | 上を削って数字に縦を回す |
| T2 | BPM の変え方 | 長押し + 左右ドラッグ(シャトル)だけ。ボタンは置かない | 見えるボタン(± など)は分かりやすいが、規約(専用ボタンを置かない)と画面の簡素さに反する |
| T3 | 操作の見つけやすさ | 隠れたジェスチャ(Sequencer と同じ) | 手引きの文字を出す(どこに、いつ出すか) |
| T4 | BPM の表示場所 | Sequencer はヘッダ右に小さく `120bpm` | 本体に巨大な数字。**両方出すと重複**だが、ヘッダ右の文字は回帰の手がかり(P5)にもなる |
| T5 | 拍子の範囲 | Sequencer と同じ 1〜16 / 2・4・8・16 | x/4 の数種に絞れば拍の表示も簡単 |
| T6 | 拍の進み具合の表示 | Sequencer のステップ編集の小節インジケータ(小さな ■ の並び、今の ■ に番号) | 遠目に分かる大きさ(拍数が少ないときは大きく) |
| T7 | 配色 | Sequencer のヘッダは青系 | メニュー(ロゴ)の緑系。**サンプルアプリの統一は Kybotos の配色が基準**で、Sequencer は追って合わせるかを別に決める |

## ゲート(必須)

1. **ステップ 0 の設計メモ(画面の案と、下の D1〜D10 の決定)をユーザーが承認するまで実装しない。**
   画面の案は Linux のスクリーンショット(試作)か、座標を書いた図で見せる。
2. **Host API / ABI は変えない**(D2 で案 B を選んだ場合だけ、その追加の文面を別に承認してから)。
3. **回帰 3 本(実機・Linux)が PASS。** metronome のシナリオは新しい画面に合わせて書き直す(conf のスキーマは変えない)。
   **mp3player / hostapi_check の `.wasm` は再ビルドしない**(highmark 不変)。
4. **描画スロットは text 80 / rect 80 の内側**(使った枚数を記録する)。
5. **app-sequencer が壊れない**(appui を変えた場合、横に置いた kybotos でビルドが通ること)。
6. 公開の repo なので、**Sequencer のコード・設計の中身は書かない**(ui-conventions に書かれている語彙の範囲で参照する)。

## スコープ

### 含む

#### ステップ 0: 設計メモ(実装なし・承認ゲート)

次を決める。各項目に推奨案を付け、画面の案を見せて選んでもらう。

- **D1: 画面の骨格と配置。** 推奨: Sequencer と同じ**ヘッダ(26px)+ ステータス行(24px)**を置き、残り(y 50〜240)を本体にする。
  - ヘッダ左 = `Metronome`(パンくずは無い。画面が 1 枚なので `<` も出さない)。
  - ステータス行右 = ▶ / ■(Sequencer と同じ位置)。**当たり判定は Sequencer より広げるか**も決める(演奏中に 1 タップで届くこと)。
  - 本体 = **BPM の巨大な数字**、**拍子**、**拍の表示**。配置の案を 2〜3 枚描いて比べる(例: BPM を上に横いっぱい、
    拍子を右に分数の形で縦に積む、拍の表示を下端に帯で)。
- **D2: 大きな数字の描き方。** 推奨: **案 A = アプリが `fill_rect` の 7 セグメントで描く**(Host API 不変。P2 / P3)。
  案 B = Host API に大きな数字の描画を足す(実機は数字だけのサブセットのフォントで flash を足す。回帰で読める。他のアプリも使える)。
  案 A なら rect の枚数の見積もりを、案 B なら API の文面とフォントの flash の増分を示す。
- **D3: BPM の変え方。** 推奨: **大きな BPM の数字の上で長押し + 左右ドラッグ = シャトル**(Sequencer と同じ段階表)。
  変更中は数字を黄で点滅(ui-conventions §4)。BPM- / BPM+ / -1 / +1 のボタンは無くす。
  範囲 40〜240、既定 120(今と同じ)。**縦ドラッグを使うか**(Sequencer の拍子と方向の衝突が無いか)も決める。
- **D4: 拍子の変え方と範囲。** 推奨: **大きな拍子の上で長押し + ドラッグ(位置)。左右 = 分子 1〜16、上下 = 分母 2 / 4 / 8 / 16、16px で 1 段**(Sequencer と同じ)。
  既定 4/4。**拍は分母の音符**(P4。6/8 は 8 分で 6 回)。変えたら今と同じく「その場で小節をやり直す」。
  範囲を絞る案(x/4 と x/8 だけ等)も比べる。
- **D5: 拍の進み具合の表示。** 推奨: **分子の数だけ枠を横に並べ、全体の幅は一定**(1 拍のときは大きく、16 拍で 1 枠 約 18px)。
  **今の拍の枠を点け、その中に拍の番号を出す**(Sequencer の小節インジケータと同じ「位置で分かるものは位置で、数字は中に」)。
  **1 拍目はアクセント色**。代案: 今の拍の番号を大きな数字で出す / 本体の背景を拍で点滅させる(焼き付きの点では有利だが目に障る)。
- **D6: 配色。** 推奨: **本体は黒**、ヘッダは**メニューの濃緑**(`MENU_BG_RGB888`)に**クリームの文字**、大きな数字はクリーム、
  拍の点灯は若葉、1 拍目のアクセントはロゴの色から 1 つ。**▶ / ■ と変更中の黄は規約の色**(ui-conventions §4。アプリをまたいで同じ)。
  **配色の値をアプリが共有する置き場所**(案: `appui` に `theme` を足し、`shared/launcher_theme.h` と値を揃える)も決める。
- **D7: BPM の文字を残すか(T4)。** 推奨: **ヘッダ右に `120bpm` を Sequencer と同じく出す**(統一感と、回帰で読める手がかり)。
  重複が気になるなら、ヘッダ右を「再生中は小節の番号」にするなどの代案を示す。
- **D8: 手引き(T3)。** 推奨: **停止中だけステータス行の左に短い手引き**(例: `hold + drag`)を暗い色で出す。出さない案と比べる。
- **D9: appui を使うか。** 推奨: **使う**(長押し・ドラッグの判定を自前で持たない。SDK のサンプルにもなる)。
- **D10: 回帰のシナリオ。** 例: `expect 120bpm; tap <▶>; expect <■の判定>; wait 2; drag <拍子> 16 0 700; expect 5/4?; tap <■>; ...`。
  ▶ / ■ は記号なので、**何で再生中を判定するか**(記号のバイト列で `expect` できるか、ヘッダ右の表示の切り替えで見るか)を確かめて決める。
  BPM のシャトルは値が揺れる(P5)ので、**シナリオでは拍子(位置で決まる)と再生 / 停止を見る**のを推奨。

## 追記 (2026-10-04): 操作を「触ってすぐドラッグ」、上下に変える

ステップ 5 で実機を触ったユーザーの指示で、操作と表示を次のように変える(ステップ 0 の D3 / D4 / D7 / D8 / D12 を置き換える)。

- **長押しをやめ、触ってそのままドラッグで値を変える。** 長押ししてからのドラッグも同じに扱う(効き方は変わらない)。
- **変える値は BPM・分子・分母の 3 つで、どれも上下のドラッグで変える**(上 = 大きく)。左右は画面の余地が無く操作しにくい。
  - BPM: シャトル(変位 = 速さ)のまま、**段階表を上下に合わせて加速を強める**(画面の端近くまで動かすと速く変わる)。
  - 分子・分母: 位置で決まる(押した位置からの変位)。確定は離したとき(D11 のまま)。
- **拍子をヘッダにも出す**(本体と同じ並びで `120bpm 4/4`)。これで拍子も回帰で読める(D12 の代案の側)。
- 手引きの文字は操作に合わせて変える。
- ui-conventions の「長押し + ドラッグ」とは違う操作になる。規約に例外として書くか、規約の側を変えるかはステップ 6 で決める。

## 追記 (2026-10-04, 2): 加速をやめ、位置で ±1 / ±10

前の追記の後に実機を触ったユーザーの指示。表示の並び・変える値の 3 つ・長押しなしはそのまま。

- **BPM も加速(シャトル)をやめ、押した位置からの変位で値を決める。上下 = ±1、左右 = ±10。**
- **拍子(分子・分母)は上下だけ**で、1 段ずつ次の値へ(左右は効かない)。
