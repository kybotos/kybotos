## 目的

CrowPanel Advance 2.8"(V1.2)に載せる **I/O 基板(rev-a)** をファームから確かめ、`docs/boards.md` に反映する。
そのうえで、基板の機能のうち**電源の自己保持(電池での起動・保持・電源断、USB での充電)**を実装する。
基板のほかの機能(残量計、ペダルの A/D、外付けの DAC、RTC)は、このフェーズでは**つながっていることの確認まで**とし、実装は後の段(26a〜)に分ける。

## 前提(着手時に実機・ソースで確かめ直す)

### P1: I/O 基板(rev-a)の構成(ユーザーから。回路の設計と設計レビューはユーザーが別の場所で済ませている)

基板は CrowPanel の J8 / J9(無線の拡張の端子)にソケットで載り、J6(MIDI)と J10(電池)へは線でつなぐ。

| 機能 | ESP32 のピン / バス | 基板の部品 | 備考 |
|---|---|---|---|
| 電源キー(HOME を兼ねる) | **IO1**(J9.7)入力 | 押しボタン → ショットキー D1 → IO1 | 押すと IO1 が約 0.3 V(LOW)。**内部プルアップが前提**(基板にプルアップは無い。今のホームキーと同じ) |
| 自己保持(HOLD) | **IO2**(J8.7)出力 | IO2 → N-ch の Q2 → P-ch の Q1(電池の経路) | **HIGH = 保持**。基板に 100kΩ のプルダウン(R3)があり、ESP32 が出力にしていない間(リセット中・起動前)は OFF |
| 電池の経路 | — | 電池 → J1 → 逆接続の保護 → Q1 → 線で **CrowPanel の J10** | ラッチが OFF の間、CrowPanel の J10 には電池がつながらない(Q1 の内部のダイオードの向きで、J10 側から電池側へは流れうる) |
| MIDI IN / OUT | **IO18 / IO17**(J6、線) | フォトカプラ TLP2361 / トランジスタ MMBT3904 | Waveshare と同じ方式。**Phase 24c と同じ設定のまま**(TXD 反転、RXD 反転なし) |
| 残量計 | I2C(IO15 / 16)**0x36** | MAX17048 | 電池側(ラッチの手前)から給電。ALRT はつながない |
| A/D(ペダル 2 本、VIN) | I2C **0x48** | ADS1115 | AIN1 = ペダル 1、AIN0 = ペダル 2、AIN3 = ペダルの電源(比で読むため)、AIN2 = VIN ÷ 2(CrowPanel の L3 が未実装なので 0 V) |
| RTC | I2C **0x52** | RV-3028-C7 | **rev-a では未実装**(部品の在庫が無かった)。ファームは「無い」ことを扱う |
| 外付けの DAC(ライン出力) | **IO10 = BCK、IO9 = DIN、IO3 = LCK**(J9) | コネクタだけ(モジュール GY-PCM5102 を線でつなぐ) | IO9 / IO10 は SGM3799 を通るので **IO45 = LOW** が要る(マイクと排他)。MCLK は使わない(モジュールの SCK = GND で内部の PLL) |

I2C のタッチ(0x38)とアドレスは重ならない。

### P2: 自己保持の回路の動き(ユーザーの設計レビューの結論)

- ボタンを押している間は、HOLD に関係なく電池の経路が ON(D1 経由で Q1 のゲートを引く)。
- **起動したら HOLD を HIGH**にすると、離しても ON のまま。**電源断はボタンが離されたのを確かめてから HOLD を LOW**(押している間は D1 経由で ON のままなので、LOW にしても切れない)。
- **USB で起動したとき(キーが押されていない)も HOLD を HIGH にする**。そうしないと Q1 が OFF のままで、CrowPanel の充電回路から電池へ**充電されない**(Q1 の内部のダイオードは充電と逆の向き)。
- ESP32 のリセット(リセットボタン、ソフトウェアの再起動、パニック、書き込み)の間は IO2 が出力でなくなり、R3 で HOLD が LOW → **電池だけで動いているときはリセットで電源が切れる**。
  これは仕様として受け入れ済み(固まったときにリセットボタンで電源を切る手段になる。Waveshare でも同じ動き)。`gpio_hold_en` で保つ変更は**しない**。
- ESP32 から「USB が挿さっているか」は直接は読めない(VIN の検知は CrowPanel の L3 が未実装で使えない)。残量計の CRATE(充放電の率)の符号で充電中かは推定できる。

### P3: 基板が届いてからの実測(ユーザー、2026-11-07)

| 状態 | 測ったところ | 値 |
|---|---|---|
| I/O 基板だけ + 電池 | 電池側の VBAT | 3.87 V |
| 同上、ボタンを押している間 / 離す | J10 へ行く側(VBAT_SW) | 3.87 V / ほぼ 0 V |
| CrowPanel に載せ、USB のみ(電池なし) | J9.3(3V3) | 3.28〜3.29 V |
| 同上 | VBAT_SW / VBAT | 4.68 V / 4.31 V(電池が無いときの充電回路の出力。CHG の LED が点く) |
| 電池のみ、今のファーム | ボタンを押している間 | CrowPanel が起動する。離すと切れる(今のファームは IO2 に触らないので正しい) |

J6(MIDI)の線と、残量計・A/D の I2C は、基板が CrowPanel に載った状態で確かめる(ステップ 0)。

### P4: 今のファーム

- CrowPanel は `KB_HAS_POWER_KEY 1` / `KB_HAS_POWER_LATCH 0`、`PIN_PWR_KEY_IN GPIO_NUM_1`。IO2 には触らない。
- `power_key.cpp` の Waveshare の動き: **起動時にキーが押されていれば**ラッチを HIGH(電池モード)、押されていなければ外部電源とみなしてラッチを触らない。
  長押し 2 秒で LOW にしてディープスリープ。**この「USB 起動では保持しない」動きは、P2 の充電の条件と合わない** → CrowPanel では変える(Waveshare は変えない)。
- I2C(I2C_NUM_1、IO15 / 16)はタッチのドライバが初期化している。

## ゲート

1. **Host API / ABI と `.wasm` は変えない。**
2. **電源の動き(いつ HOLD を上げるか、長押しで何をするか、USB があるときの長押し)の案は、実装の前にユーザーの承認を得る**(ステップ 0 の結果を添えて提案する)。
3. **Waveshare の動きは変えない**(電源キー・ラッチ・電池の検知・回帰の数値)。CrowPanel の分岐はボードの記述の定数で持つ(基板固有の if を共通コードに散らさない)。
4. 一時的な計測コードは `PHASE26-TEMP` の目印を付け、済んだら撤去して `git diff` で残りが無いことを確かめる(workflow.md §3.2)。
5. 回帰のしきい値(`scripts/device-regress.conf`)を変えたくなったら、変える前にユーザーの承認を得る。
6. **電池の抜き挿し・線のつなぎ替え・USB の抜き挿しはユーザーの作業**。この指示書は手順を代行しない。電池で動かすと USB のシリアルが使えないので、その間の確認は画面かテスターで行う。
7. 公開の repo なので、非公開の repo の中身は書かない。I/O 基板について書くのは、ファームに関係する事実(ピン、アドレス、動き、実測)だけにする。

    0x36 は版の情報(VERSION レジスタ)、0x48 は設定レジスタの既定値を 1 回読み、デバイスが正しく応答することを確かめる。

  - e. 結果をまとめ、`docs/boards.md` に反映する案(§3-1 の GPIO1 / 2 / 3 / 9 / 10 / 45 の行、§3-3 の端子、§4 の電源キー / 自己保持 / 電池の行、I/O 基板の節)を作る。
    **電源の動きの案(ゲート 2)**を作って承認を得る。案に含めること:
    - 起動時に HOLD を上げる条件(キーの有無によらず常に、を基本案とする)と、上げるまでの時間(起動の早い段階で。ボタンを離すまでに間に合うこと)。

    - USB が挿さっているときの長押し(HOLD を下げても電源は切れず、充電も止まる)の扱い。例: 画面に「USB 接続中は電源を切れません」と出して HOLD は下げない、など。

## 追記 (2026-11-07): ステップ 0 の結果と、承認された電源の動き

- **0-c(MIDI)は後回し**: I/O 基板の MIDI の IN / OUT はまだ配線していない(ユーザー)。配線後に行う。ほかの 0-a / 0-b / 0-d は済み(`docs/results/phase26.md`)。
- **承認された電源の動き(ゲート 2、ユーザー承認 2026-11-07)**。CrowPanel だけ。Waveshare は変えない:
  - 起動時は**キーの有無によらず HOLD を HIGH**(PowerKey の init の最初で。100ms の LOW は入れない)。
  - **2 秒の長押し → キーが離されるのを待つ → 実行中のアプリを止める(強制ホームと同じ経路、止まるのを待つ)→ HOLD を LOW**。ディープスリープには入らない。
  - **HOLD を LOW にして 1 秒後も動いていれば USB 給電中とみなし、HOLD を HIGH に戻す**(充電の再開)。**画面にメッセージは出さない**(ログだけ)。
  - 強制ホームは 1〜2 秒で離したとき(Waveshare の電池モードと同じ区切り)。

## 追記 (2026-11-07): 長押しは押したままで切る

- 実機で確かめたユーザーの判断: 「2 秒以上押して離すと切れる」は分かりにくいので、**押したままで切れる**ようにする。
  回路上、押している間は D1 経由で電池の経路が ON のままなので、**2 秒に達した時点(押したまま)でアプリを止め、バックライトを消し、HOLD を LOW** にする。
  実際に電源が落ちるのは離したとき(Waveshare の「押したまま LOW + ディープスリープ」と同じ見え方)。
  **USB 給電中は、離してから 1 秒後も動いていれば HOLD とバックライトを戻す**。上の追記の「離されるのを待ってから止める」はこれで置き換える。

## 追記 (2026-11-07): 充電の制約(完了条件 2 の変更)

- 実機で、**TP4059 は電池が一度見えなくなると DONE に入り、HOLD を上げても充電を再開しないことがある**と分かった(`docs/results/phase26.md` ステップ 2)。
  電源が切れた状態で USB を挿したとき・ESP32 のリセットのたびに HOLD は約 1 秒 LOW になるので、**rev-a ではファームで確実な充電にできない**。
- ユーザーの判断: **制約として記録して進める**。当面の使い方は「**充電するときは、電池で起動してから USB を挿す**」。`docs/boards.md` に書き、回路側の対策(USB があるときは
  ファームに関係なく Q1 を ON にする、など)と原因の切り分けは roadmap の課題に残す。
- 完了条件 2 の「USB で起動したときに電池が充電される」は、「**電池で動作中に USB を挿すと充電される**。USB で起動したときは充電されないことがあり、その制約を記録している」に読み替える。
  「満充電で 4.2 V を超えない」は、上の使い方で満充電まで充電したときに確かめる(時間がかかるので、締めまでに済まなければ記録に残して課題へ)。
