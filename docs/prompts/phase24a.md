## 目的

CrowPanel Advance 2.8"(V1.2)は Phase 24 で画面・SD・シリアルのコマンドまで動いたが、**タッチは I2C のスキャンだけ**で、指では操作できない
(シリアルの `tap` などの注入だけが効く)。このフェーズで CrowPanel のタッチの IC を読み、**指で Waveshare と同じように操作できる**ようにする。
CrowPanel を「Waveshare の水準」(`docs/results/phase24.md` 0-e)へ上げる段階の 1 段目(24a → 24b 音と SD → 24c MIDI と BOOT ボタン)。

## 前提(Phase 24 で確かめたこと。着手時に確かめ直す)

- **P1: タッチの IC は 0x38 だけが応答した**(I2C の 0x08〜0x77 のスキャン、port 1、100kHz、SDA=IO15 / SCL=IO16)。GT911 の 0x5D / 0x14 は応答しない。
  工場出荷時のファームは GT911 のドライバを使っていたが、wiki と同梱のデータシートの **FT6336U(FocalTech、FT5x06 / FT6x36 系)** と合う。
- **P2: 回路図(V1.2)で INT=IO47(`IO47_TP_INT`)、RST=IO48(`IO48_TP_RST`)**。Phase 24 ではどちらにも触れていない(リセットせずに応答した)。
  ベンダーのサンプルにある「GPIO1 / 2 でアドレスを選ぶ手順」は GT911 用で、FT6336 には要らない見込み。IO1 / 2 は無線モジュールの端子なので**触らない**。
- **P3: FT6336U のデータシート**(`Datasheet/D-FT6336U-DataSheet-V1.0(1).pdf`)にあるのは電気的な仕様だけで、**レジスタの表は無い**。
  分かること: I2C は 10〜400kHz、RSTN は Low でリセット、**リセットは 5ms 以上、解除から報告の開始まで 300ms 以上**(Trst / Trsi)、電源投入から報告まで 300ms 以上(Tpon)、
  1 点と 2 点のタッチ、報告は最大 100Hz、INT は「読めるデータがある」ことを知らせる。
- **P4: レジスタは FocalTech の FT6x36 系で広く知られた配置を使い、実機で読んで確かめる**: `0x02` TD_STATUS(下位 4 bit が点の数)、
  `0x03`〜`0x06` 1 点目(`0x03` の上位 2 bit がイベント(押した / 離した / 押している)、下位 4 bit が X の上位、`0x04` が X の下位、`0x05` の下位 4 bit が Y の上位、`0x06` が Y の下位)、
  `0xA3` チップ ID、`0xA4` G_MODE(INT の出し方)、`0xA6` ファームの版、`0xA8` ベンダー ID。レジスタのアドレスは **8 bit**(CST328 は 16 bit)。
- **P5: いまの `touch.cpp` の形**: I2C の新 API。CST328 の読み出し(`read_raw_point`)→ 生の座標の範囲の学習(`update_calibration`、CST328 は固定の範囲で初期化済み)→
  正規化(`normalize`)→ 回転とスケール(`map_basic_to_display`、`TOUCH_ROT`)→ LVGL。**注入(`touch_inject`)は LVGL の読み取りの段で差し込む**ので IC に依存しない。
  INT は使わずに常にポーリング(`TOUCH_FORCE_POLL 1`)。押すたびに座標をログに出す(`TOUCH_LOG_TAP` / `TOUCH_LOG_BASIC`)。
  `DEBUG_TOUCH_CURSOR` を定義すると、画面にカーソルと座標のラベルを出せる(一時の確認用)。
- **P6: 液晶の向き**は Waveshare と同じ設定で正しく出た(Phase 24)。LVGL の論理座標は 320×240 で、パネルは 240×320 を回して使っている。
  **タッチの生の座標の向き(縦置きの 240×320 か、横置きか、反転しているか)は未確認。**
- **P7: I2C のバスは外部の J7(3.3V-I2C)と共用**。手元の CrowPanel の J7 には何もつないでいない。

## ゲート

1. **ステップ 0 の設計メモ(`touch.cpp` の分け方、リセットと INT の扱い、座標の変換の決め方)をユーザーが承認するまで実装しない。**
2. **Waveshare は変えない**: 回帰 3 本 PASS、開始時の `free_int` / `largest_int` と highmark が Phase 24 と同じ(違えば理由を書く)。CST328 の読み出しの挙動を変えない。
3. **Host API / ABI と `.wasm` は変えない**(タッチはホストの中の話)。
4. **出力にするピンは IO48(RST)だけ**(使うと決めた場合)。IO47(INT)は入力。それ以外のピンに触れない。
5. 公開の repo なので、非公開の repo の中身は書かない。

## スコープ

### 含む

- **ステップ 0: 確認と設計メモ**(`docs/results/phase24a.md`)
  - **0-a 実機で読む**: 一時のコード(`PHASE24A-TEMP`)で、`0xA3`(チップ ID)/ `0xA6` / `0xA8` と、指で押したときの `0x02`〜`0x06` を読んでログに出す。
    リセットありとなし(IO48)、INT(IO47)の動きもここで見る。押す位置はユーザーに頼む(四隅と中央。どの角を押したかをユーザーが伝える)。
  - **0-b 設計メモ**。決めること:
    - **a. `touch.cpp` の分け方**: IC ごとの「生の座標と押しているかを読む」部分だけを分け(たとえば `touch_cst328.cpp` / `touch_ft6336.cpp`、または `touch.cpp` の中の `#if`)、
      LVGL の読み取り・注入・正規化・回転は共通に残す。ボードの記述は `KB_TOUCH_IC` に `KB_TOUCH_IC_FT6336` を足す。
      **Waveshare のコードの経路が変わらない**こと(ゲート 2)を、どう確かめるかも書く。
    - **b. リセットと INT**: IO48 でリセットするか(するなら Trst ≥ 5ms、Trsi ≥ 300ms を待つ。起動時間への影響)、INT を使うかポーリングのままか(推奨はいまと同じポーリング)。
    - **c. 座標の変換**: 生の範囲(FT6336 は自分の分解能を返さない見込みなので、0〜239 / 0〜319 を定数で持つか)と、回転・反転を
      **ボードの記述の定数**にする(Waveshare の `TOUCH_ROT` などもそこへ移すか)。範囲の学習(`update_calibration`)を FT6336 でも使うか。
    - **d. 2 点目**: 使わない(CST328 と同じく 1 点目だけ)ことの確認。
    - **e. 確かめ方**: 注入と指が同じ座標になることを、何で判定するか(下の「確認の方法」)。
- **ステップ 1: 実装**(承認された方式で)。Waveshare の回帰を先に回してゲート 2 を確かめ、それから CrowPanel。
- **ステップ 2: CrowPanel での確認**(ユーザーの操作 + ログ + カメラ):
  - **座標**: `DEBUG_TOUCH_CURSOR` を一時に有効にしたファーム(または押した座標のログ)で、四隅と中央を押し、表示の座標が指の位置と合うこと(誤差の目安は数ピクセル。端まで届くこと)。
  - **操作**: 指で、メニューからアプリを起動 → metronome の ▶ / ■、BPM と拍子の上下のはじき(±1)、BPM の押したまま(±5 → ±10)→ ヘッダ右の `Settings` を開いて
    バーのタップ・スクラブ、取っ手を上へ払って閉じる → mp3player の一覧の縦スワイプ → スクリーンセーバーをタッチで解除(解除のタップでアプリを起動しないこと)。
  - **注入との一致**: 同じ場所を指と `tap` で押したときに、同じ部品が反応すること(`texts` とログ)。
  - Waveshare と並べて、押した感じ(反応の遅れ、取りこぼし、はじきの判定)に違いが無いかをユーザーに見てもらう。
- **ステップ 3: 文書**: `docs/results/phase24a.md`、README のボードの表(CrowPanel の状態)、`docs/workflow.md`(要れば)、`docs/lessons.md`(要れば)、roadmap。

### 含まない

- 音・SD の検証(24b)、MIDI と BOOT ボタン(24c)。
- ジェスチャー(FT6336 の内蔵のジェスチャー)、2 点のタッチ。
- J7 の I2C に機器をつなぐこと。
- タッチの回帰の自動化(注入は IC を通らないので、IC の読み出しは人間の操作で確かめる。自動の回帰は今までどおり注入で回す)。

## 完了条件

1. CrowPanel で、指でメニューからアプリを起動でき、metronome・Settings・mp3player の一覧・スクリーンセーバーの解除を指で操作できる(ユーザーの確認)。
2. 四隅と中央で、指の位置と LVGL の座標が合っている(記録に数値)。注入(`tap`)と指で同じ部品が反応する。
3. チップ ID などのレジスタの値と、リセット・INT の扱いを記録に残している。
4. Waveshare: 回帰 3 本 PASS、数値が Phase 24 と同じ(違えば理由)。Host API / ABI・`.wasm` 不変。
5. 記録 `docs/results/phase24a.md`。
