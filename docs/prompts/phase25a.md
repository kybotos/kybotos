- 契約日: 2026-11-03

  `wasm-apps/appui/src/theme.rs`(アプリの骨格: ヘッダ 26px)、`wasm-apps/metronome` / `wasm-apps/mp3player`、`wasm-apps/README.md`(`.wasm` のビルドとコミット)、

## 目的

25 で読めるようになった電池の残量を、**メニューもアプリの中も含めて、画面の右上に常に表示する**(ユーザーの指示)。
場所を節約するため、USB 給電中は「USB の記号 + 残量」の形にする(USB の文字は使わない)。

## 決まっていること(ユーザーの指示 2026-11-03)

- **表示する場所は、画面の右上(ヘッダの右端)**。メニューでも、アプリの中でも出す。
- **USB 給電中(電源キーで起動していないとき)は、記号 + 数字(例: USB の記号 + `98%`)の両方を出す。** 電池で動いているときは数字だけ(例: `98%`)。
  USB 給電中は電圧が約 50mV 高く、電池なしでも 99〜100% に見える(25 の実測)ことを承知の上で、値を出す。
- 電池の検知が無いボード(CrowPanel。`KB_HAS_BATT_SENSE 0`)では出さない。

## 前提(着手時にソースと実機で確かめ直す)

- **P1: 取り出す口**(25): `battery::Get(&r)`(`r.mv` / `r.pct`、ロック不要、更新は約 1.6 秒おき)。電池の検知が無い・最初のサンプル前は false。
- **P2: USB 給電かどうか**: `PowerKey::is_battery_mode()`(電源キーで起動した = 電池モード = false なら USB 給電で起動)。起動時に決まり、あとから USB を挿しても変わらない
  (その場合は残量が数十 mV 高めに出るが許容する)。`battery` に「USB 給電」のフラグを渡す小さな口(例 `battery::SetExternalPower(bool)`)を足し、`app_main.cpp` から電源キーの初期化の後に呼ぶ。
- **P3: 画面の構造**: アプリは自分の画面(ホストの retained なスロットで描く。`texts` で列挙される)を持ち、メニューは LVGL の画面。**ホストが持つ部品は `lv_layer_top()` に置くと、画面の切り替えやアプリの描画の影響を受けずに常に上に出る**
  (25 の一時の計測コードで、この方法で左下に出して使えた)。クリックを受けない部品にして、タッチはその下のアプリへ通す。
- **P4: 右上の取り合い**(ここがこのフェーズの本体。着手時に実際の座標で確かめる):
  - メニューのヘッダ右は `Settings`(文字の右端 310、当たり判定 x 220〜320)。バッジの分だけ左へずらす。
  - mp3player はヘッダ右に曲の位置(`1/10`、x 279 付近)を出している。metronome のヘッダ右は(着手時に確認)。
  - 非公開の app-sequencer のアプリは、ヘッダ右に BPM / 位置の表示と操作(x 200〜320)がある。**この repo では直せないので、バッジとの重なりを記録して追従を別の作業にする**。
  - 予約する領域は右上の約 44px × 16px を目安に、実際の文字の幅(数字 3 桁 + `%`、USB の記号)から決める。
- **P5: 記号**: 実機のフォントは FontAwesome の記号を持つ(`LV_SYMBOL_USB` が使えるかを実機で確かめる。無ければ、画像や図形、文字で代える)。
  Linux ホストは記号を図形で描く(`appui` の記号と同じ扱い)。
- **P6: メモリの余裕**: 回帰の `MIN_FREE_INT` との余裕は **460B**(25)。LVGL の部品(ラベル + タイマー)が内部メモリを使うなら、回帰が割る可能性がある。測ってから、割るなら更新を先に相談する(ゲート 4)。

## ゲート

1. **Host API / ABI は変えない。** バッジはホストが画面に重ねる部品で、アプリには何も増やさない。アプリの `.wasm` を作り直す場合(ヘッダ右の部品を左へ寄せるなど)は、レイアウトの変更だけにとどめる。
2. **既存アプリのヘッダ右の部品を動かす・消す変更は、実装の前に新しい座標をユーザーに示して承認を得る**(`.wasm` を再ビルドしてコミットするため。`wasm-apps/README.md` の手順)。
3. 一時的な計測コードは `PHASE25A-TEMP` の目印を付け、済んだら撤去して `git diff` で残りが無いことを確かめる。
4. **回帰のしきい値(`scripts/device-regress.conf`)を変えたくなったら、変える前にユーザーの承認を得る**(25 の記録: 余裕 460B)。
5. 公開の repo なので、非公開の repo の中身は書かない(app-sequencer のヘッダ右の衝突は「非公開のアプリに追従が要る」とだけ書く)。

## スコープ

### 含む

- **ステップ 0: 確認と設計**
  - 各画面のヘッダ右の使われ方を実座標で洗い出す(メニュー、Settings、metronome、mp3player、`wasm-apps/dev/` の検査アプリ、Linux ホスト)。
  - バッジの形(USB の記号、数字、`%`、色)と置く座標、動かす部品の新しい座標を決め、ユーザーに示して承認を得る(ゲート 2)。色は Phase 22d / 22e の配色に合わせ、残りが少ない(例 20% 以下)ときは赤系の文字にする(警告の動作は 25b)。
  - スクリーンセーバー(減光・消灯)の間はバッジを出さない / 暗くする(焼き付きを避ける。`screensaver.cpp` の状態に合わせる)。
- **ステップ 1: 実機(ESP32)**: `lv_layer_top()` にバッジを置き、`lv_timer`(約 2 秒)で `battery::Get` を読んで更新する(新しいタスクは作らない)。電池の検知が無いボードでは何も作らない。
  メニューの `Settings`(位置・当たり判定)を、新しい座標へずらす(`shared/launcher_theme.h` の定数)。
- **ステップ 2: アプリのヘッダ右**: 重なる部品(mp3player の曲の位置など)を左へ寄せ、`.wasm` を再ビルドしてコミットする(承認済みの座標で)。回帰のシナリオ(座標に依存)が通ること。
- **ステップ 3: Linux ホスト**: 同じ位置に同じ見た目で出す。電池が無いので**模擬値**(環境変数 `KYBOTOS_SIM_BATT=<0..100>` で電池、`usb<0..100>` で USB + 値、未設定なら出さない)。画面を撮って見た目を確かめる(workflow §3.6)。
- **ステップ 4: 確認と後片付け**
  - 実機: メニューとアプリ(metronome / mp3player)の画面を撮り、バッジが右上に出て、ほかの部品と重ならず、タッチ(戻る、`Settings`、アプリの操作)が変わらないことを確かめる。
    USB 給電(電源キーで起動していない)と電池モード(電源キーで起動)の両方の見た目を確かめる(電池モードは USB が無いので、画面を撮るか目視。カメラは workflow §3.3)。
  - Waveshare の回帰 3 本 PASS(数値を記録)。CrowPanel は何も出ない(ビルドと起動)。
  - 普段使い(`KYBOTOS_DEV_APPS=0`)のファームに戻し、SD の検査用アプリを消す。
  - 文書: `docs/results/phase25a.md`、README、`docs/boards.md`、roadmap(25a を done。25b へ)、status、`docs/workflow.md` / `docs/lessons.md`(要れば)。

### 含まない

- 低電池の警告・自動の電源断(25b)、アプリへ出す Host API(25c)。
- 充電中の判定、残量の学習、残量のカーブの見直し(25b の放電の実測で行う)。
- **非公開の app-sequencer のアプリのヘッダ右の直し**(重なりの記録だけ。追従は別の作業)。
- CrowPanel の電池の検知(基板が届いてから。Phase 26)。

## 完了条件

1. Waveshare の画面の右上に、メニューでもアプリの中でも、残量が出る。USB 給電(電源キーで起動していない)のときは記号 + 数字、電池モードでは数字だけ。残りが少ないときは色が変わる。
2. バッジが既存の部品と重ならず(メニューの `Settings`、mp3player / metronome のヘッダ)、タッチが従来どおり動く。スクリーンセーバー中は出ない / 暗い。
3. Linux ホストでも同じ位置・見た目で出る(模擬値)。Host API / ABI は不変。`.wasm` を作り直した場合は再ビルドしてコミットしている。
4. Waveshare の回帰 3 本 PASS、CrowPanel は何も出ずにビルド・起動する。普段使いのファームに戻し、SD の検査用アプリを消している。
5. 記録・roadmap・status を更新し、非公開のアプリの追従が要ること(重なる座標)と、25b への引き継ぎを書いている。

## 追記 (2026-11-03): 表示の形と座標の承認(ゲート 2)

ユーザーがモックアップ(`captures/phase25a/mock.png` / `mock2.png`。git の対象外)を見て決めた。

- **USB の記号は使わない。USB 給電中は「白抜き」**(地を文字色で塗り、数字を暗い色にする)。電池で動いているときは普通の色(クリーム)の文字。20% 以下は赤(USB のときは赤の白抜き)。
  電池の数字は `%` つき(`64%`、`100%`)。
- **右端 316 に右寄せ、ヘッダの文字と同じ行(y=5)。予約する領域は x ≥ 276**(最大の `100%` の白抜きで x0 ≈ 277)。白抜きの地は x0〜320、y 3〜23。
- **動かす部品の新しい座標**:
  - メニューの `Settings`: 文字の右端 310 → **270**、当たり判定 x 220〜320 → **x 196〜274**。
  - metronome: `120bpm` x 200 → **186**(ヘッダのドラッグの当たり判定 x 180〜244)、`4/4` x 268 → **246**。
  - mp3player: 曲の位置 `1/10` の右端 312 → **270**。
  - 非公開の app-sequencer のアプリ(BPM / 位置が x 206〜316)は、この repo では直さない(重なりを記録して追従を別の作業にする)。
- `.wasm`(metronome / mp3player)は再ビルドしてコミットする。
